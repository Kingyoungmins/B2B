# axcell_addon 통합 기록 + 리뷰 잔여 항목 (2026-08-28)

wcoh 전달분(`axcell_addon/`)을 **B2B ver0.8.0 본체에 이식**하면서 남기는 기록입니다.
이식 전에 애드온 코드 전체를 리뷰했고(10개 관점 · 34건 확인), 그 중 **본체 경계에서 막아야 할 것과
한 줄짜리 버그는 이식하면서 고쳤고**, 설계 판단이 필요한 것은 아래에 목록으로 남깁니다.

> `axcell_addon/` 폴더는 전달받은 그대로 두었습니다. 실제로 도는 복사본은
> `b2b_scheduler.py` · `b2b_telemetry.py`(루트), `scripts/scheduler.js` · `whoami.js` · `embed.js`, `styles/scheduler.css` 이고,
> 아래 "이식하면서 고친 것" 만큼 원본과 다릅니다. wcoh 쪽 마스터에 반영해 주시면 다음 전달 때 다시 벌어지지 않습니다.

## 3. 판단이 필요해 남겨 둔 것 (wcoh 쪽 결정 사항)

동작을 바꾸는 것이라 임의로 고치지 않았습니다. 심각한 순.

1. **cron.txt 가 '한 번만' 을 표현하지 못함** — `M H DD MM *` 는 매년 반복이고, `parse_cron_expr` 이 `date` 를 복원하지 못해 1회 스케줄은 수정/재등록 시 날짜를 다시 입력해야 함(저장 버튼 비활성). 말일 처리(`29~31일은 말일에 실행` 안내)도 인코딩되지 않음. → 실행 주체를 만들기 전에 **`schedule.json` 을 실행 근거로 승격**하거나 cron 확장 표기를 정하는 편이 안전합니다.
2. **유령 입력 판정이 0.8.0 스킬에서 동작하지 않음** — 0.8.0 의 `save-load.js` 는 v3 매니페스트만 씁니다(`requiredFiles`·`unresolvedRefs` 없음). `pipeline.js` 는 새 스텝마다 활성 탭을 `targetFileId` 로 찍으므로 문서화된 '활성 탭 유령' 이 걸러지지 않고, 스킬이 읽지 않는 파일에도 AX-Trace 연결을 요구합니다. README 의 "실물 스킬로 일치 확인" 은 v4 스킬 기준입니다.
3. **출력 문서도 AX-Trace 를 요구** — `analyze()` 가 `role="output"` 으로 분류한 문서(`ctx.book("결과.xlsx").write(...)`)가 `readiness()`/서버 완결성 검사에서 그대로 카운트됨. 파이썬 쪽 `skill_docs_from_zip` 은 출력 판정 자체가 없음.
4. **스킬이 아닌 파일이 AX-Cell 자리를 차지** — 클라/서버 모두 "스킬로 못 읽음 = 통과" 라서 xlsx 나 `.logic.json` 없는 zip 이 AX-Cell 로 교체·등록됨("애매하면 멈춘다" 원칙과 반대).
5. **스케줄 수정 후 목록 문장이 옛 값** — `update_schedule` 이 cron.txt 만 쓰고 `schedule.json` 의 `summaryWhen` 은 안 바꿔, 카드에 '매달 1일 09:00' 옆에 `0 18 * * 1` 이 나란히 보임. INTEGRATION.md 말미의 제안대로 `_write_schedule_files()` 를 타게 하면 해결(단, docs/cellSkillName 을 schedule.json 에서 읽어 채워야 함).
6. **같은 이름 재등록 시 옛 zip 잔존** — `mkdir(exist_ok=True)` 후 새 파일만 써서 AX-Cell zip 이 2개가 되고 `createdAt` 이 초기화됨. 재등록이면 스킬 파일을 먼저 비우거나 `createdAt` 을 이어받아야 함.
7. 그 외: `embed.js` 의 iframe `load` 는 X-Frame-Options 차단 페이지에서도 발생해 실패 패널이 뜨지 않음 / `refreshSummary()` 가 필수 필드를 비우는 첫 키 입력에서 전체 재렌더(포커스 이탈) / `telemetry_preview.jsonl` 무한 증가 / 등록 요청의 `docs` 를 서버가 클라 계산값 그대로 신뢰.

## 4. 이식 후 실측

`python serve_b2b.py`(포트 18095)로 확인:
- `GET /api/whoami`, `GET /api/scheduler/list` 정상 · 외부 Origin 이면 둘 다 **403**
- `POST /api/scheduler/delete` 외부 Origin **403**, 자기 Origin 이면 모듈 응답
- 본문이 깨진 JSON 이면 소켓 끊김 대신 **500 JSON**
- `index.html` 에 `sched-root` / `page-trace-generator` / `schedlist-root` / `user-identity` / 새 script·css 태그 서빙 확인
- 기동 시 `addon.telemetry.init` trace 기록, `/api/app/shutdown` 경로에서 `_addon_telemetry_stop` 통과
- `tools/okf/regen.py` 재생성 → `check_okf.py` "최신 상태 ✓"

**아직 안 되는 것(설계대로)**: 등록한 스케줄을 실제로 실행하는 주체. `cron.txt` 는 기록일 뿐입니다.
