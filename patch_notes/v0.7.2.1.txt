AX-Cell — 업데이트 안내 (0.7.2.1, 2026-08-10 갱신)
====================================================

이 문서는 0.7.1 이후에 바뀐 내용(0.7.2 · 0.7.2.1)을 정리한 안내입니다.
0.6.1 ~ 0.7.1 내용은 이전 문서(v0.7.1.txt)를 봐 주세요.


────────────────────────────────────────────────────
[ 핵심 요약 — 이번에 좋아진 점 ]
────────────────────────────────────────────────────

1. 프로그램 이름이 'AX-Cell' 로 바뀌었습니다. 화면 맨 위에 지금 쓰는 버전도
   함께 보입니다 (예: AX-Cell  ver 0.7.2.1).

2. 파일 올리는 게 빨라졌습니다. 큰 파일일수록 차이가 큽니다.
   (47MB 파일 기준 20초 → 13초. 같은 파일을 두 번 읽던 것을 한 번으로 줄였습니다)

3. 단계를 적용할 때도 빨라졌습니다. 되돌리기용 백업을 뜨는 시간을 크게 줄였습니다.
   (되돌리기 기능은 그대로입니다)

4. 오류가 났을 때 설명이 훨씬 친절해졌습니다. 무엇이 잘못됐는지 콕 집어 말하고,
   오류 창에 그대로 붙여넣을 문장까지 알려 드립니다.

5. [🔄 새로고침] 이 훨씬 똑똑해졌습니다. 스킬을 처음부터 다시 돌리지 않고
   작업하던 상태 그대로 되살립니다. 실행기에서 고른 파일 짝도 기억합니다.

6. 피벗 만들 때 "머리글이 2번째 줄에 있어요" 같은 표를 잘 처리합니다.
   예전에는 이런 표에서 스킬이 통째로 실패하는 경우가 있었습니다.


────────────────────────────────────────────────────
[ 8월 10일 업데이트 (0.7.2.1) — 속도 개선 ]
────────────────────────────────────────────────────

● 파일 업로드가 약 2배 빨라졌어요
   - 프로그램이 파일을 올릴 때, 같은 파일을 두 번 읽고 있었습니다.
     한 번은 수식(=SUM(...) 같은 것)이 뭔지 보려고, 또 한 번은 그 수식의
     계산 결과를 보려고요.
   - 그런데 두 번째 읽기는 '수식이 있을 때만' 쓸모가 있습니다. 청구내역처럼
     숫자만 들어 있는 파일에서는 통째로 헛일이었습니다.
   - 이제 수식을 발견했을 때만 두 번째로 읽습니다.
        · 수식이 없는 파일 → 시간이 절반으로 줄어듭니다
        · 수식이 있는 파일 → 예전과 똑같이 동작합니다 (손해 없음)
   - 실제 업무 파일 183개로 결과가 예전과 한 글자도 다르지 않은지 모두 확인했습니다.

● 단계를 적용할 때 기다리는 시간이 줄었어요
   - 단계를 적용하기 전에 프로그램은 '되돌리기용 백업'을 뜹니다(끄기/되돌리기를 위해).
     그런데 이 백업이 사용자가 내려받는 파일과 똑같은 취급을 받아, 저장 앞뒤로
     불필요한 준비/정리 작업을 하고 있었습니다.
   - 백업은 화면에 보이지 않는 내부 파일이라 그 작업이 필요 없습니다. 건너뛰도록 했습니다.
        · 백업 뜨는 시간 387ms → 44ms
   - 되돌리기(단계 끄기)는 예전과 똑같이 동작합니다. 실제 엑셀로 확인했습니다.

● 속도 관련해서 검토했지만 하지 않은 것 (참고)
   - 임시 파일을 메모리(RAM)에 올려 빠르게 하는 방법을 실제로 측정해 봤습니다.
     효과가 0.1% 밖에 없어 적용하지 않았습니다.
   - 이유: 윈도우가 이미 최근 읽은 파일을 메모리에 들고 있어서, 파일을 읽는 데는
     거의 시간이 안 듭니다(68MB 읽기에 0.02초). 오래 걸리는 건 '읽어오는 것'이 아니라
     '엑셀 파일 내용을 해석하는 계산'이라 파일을 어디에 두든 줄지 않습니다.
   - 메모리 부족 위험만 떠안고 얻는 게 없어 접었습니다.

● 참고: 파일이 크면 어차피 오래 걸립니다
   - 47MB 파일 하나가 6MB짜리 파일 3개보다 100배 넘게 걸립니다.
     가능하면 파일을 나눠서 올리는 게 어떤 방법보다 효과가 큽니다.

[ 0.7.2 업데이트 — 이름 변경 · 오류 안내 · 새로고침 ]
────────────────────────────────────────────────────

● 프로그램 이름이 'AX-Cell' 로 바뀌었어요
   - 화면 곳곳의 'B2B 빌링 Agent' 표기가 모두 'AX-Cell' 로 바뀌었습니다.
   - 화면 맨 위 제목 옆에 지금 쓰는 버전이 초록색으로 보입니다.
        AX-Cell  ver 0.7.2.1
   - 이 숫자는 프로그램 파일 속성(자세히 → 파일 버전)의 값과 항상 같습니다.
     문의하실 때 이 숫자를 알려 주시면 확인이 빠릅니다.
   - 상단 메뉴의 '사용 가이드' 항목은 없앴습니다.

● 오류가 났을 때 설명이 친절해졌어요
   - 예전에는 "무언가 맞지 않아 진행이 멈췄습니다" 정도로만 나와서, 무엇을 해야 할지
     알기 어려웠습니다.
   - 이제는 실패한 코드와 파일 구조까지 같이 살펴보고 원인을 콕 집어 말합니다.
     그리고 마지막에 오류 창 메모칸에 그대로 붙여넣을 문장을 알려 드립니다.
   - 예시:
        "피벗을 만드는 명령에 제가 알지 못하는 설정이 하나 있었어요
         (머리글이 몇 번째 줄인지 지정하는 부분). 무엇을 하려 하셨는지는 이해했습니다.
         아래 문장을 오류 창 메모칸에 넣고 [에러 복구 시도] 를 눌러 주세요.
         "VIEW 시트의 표는 머리글이 2번째 줄에 있어요. 서비스별로 할인 후 금액을
          합계로 더한 요약표를 새 시트에 만들어 주세요.""
   - AI 도움의 답변도 같은 눈높이로 맞췄습니다. 개발자 용어 대신 쉬운 말로 답합니다.

● [🔄 새로고침] 이 작업 상태를 그대로 되살려요
   - 예전에는 새로고침하면 스킬을 처음부터 다시 돌려서 오래 걸렸습니다.
     이제 적용이 끝난 상태를 그대로 되살려 기다림이 크게 줄었습니다.
   - 실행기에서 고른 '파일 짝'(스킬이 찾는 파일 ↔ 실제 올린 파일)도 함께 기억합니다.
     예전에는 이게 사라져서, 새로고침 뒤 자동으로 다시 적용하다 실패하곤 했습니다.
   - 되살리다 실패하면 조용히 넘어가지 않고 오류 창으로 알려 드립니다.

● 피벗이 '머리글이 2번째 줄'인 표를 잘 처리해요
   - 1번째 줄이 제목이고 2번째 줄이 머리글인 표가 많습니다.
     이런 표에서 피벗 스킬이 통째로 실패하는 경우가 있었습니다.
   - 이제 머리글 위치를 알려 주지 않아도 알아서 찾습니다.
   - 스킬이 없는 설정을 잘못 쓴 경우에도, 무엇을 쓸 수 있는지 알려 줘서
     [에러 복구 시도] 한 번으로 고쳐집니다.

● 피벗 값 항목이 '건수' 로 제대로 나와요
   - "값: 개수:상품명" 처럼 행에 넣은 항목을 값에도 넣으면, 표가 총합 한 줄로
     찌그러지던 문제를 고쳤습니다.

● 지난달 · 이번달 파일이 섞여도 헷갈리지 않아요
   - 4월에 만든 스킬을 5월 파일에 쓸 때, 스킬이 4월 파일과 5월 파일을 둘 다
     달라고 하던 문제를 고쳤습니다.
   - 스킬 저장할 때 뜨는 기본 이름도 '지금 올린 파일' 기준으로 바뀝니다.
     (예전에는 지난달 파일명이 그대로 떴습니다)

● 엑셀 창이 이상하게 뜨던 문제들
   - 단계를 껐다 켠 뒤 실행기로 넘어가면 회색 빈 엑셀 창이 겹쳐 보이던 문제
   - 단계를 끄면 엑셀 창이 갑자기 최대화되던 문제
   - 껐는데도 값이 그대로 남아 있던 문제 (빠르게 여러 번 껐다 켤 때)
   위 세 가지를 고쳤습니다.

● 창 크기 조절 손잡이가 잘 보여요
   - 대화창 · 입력창 · 스킬 목록의 크기를 조절하는 손잡이가 잘 안 보였습니다.
     빗금 무늬를 넣어 마우스를 올리면 바로 알아볼 수 있게 했습니다.

[ 관리자용 안내 ]
────────────────────────────────────────────────────

● 버전 확인 기능이 생겼어요 (F9 → 개발자 설정)
   - 지금 쓰는 프로그램 버전과, 회사 서버에 올려 둔 최신 버전을 비교합니다.
   - '버전 서버 실제 주소' 한 칸만 넣으면 됩니다. AI 서버와 같은 통로로 나갑니다.
   - 지금은 확인만 합니다. 버전이 다를 때 "최신버전을 다운로드 해주세요" 안내창을
     띄우는 기능은 다음에 붙일 예정입니다.

● 문제 확인용 기록이 자세해졌어요
   - 파일을 올릴 때 각 단계가 몇 초 걸렸는지 기록에 남습니다.
   - "느리다" 는 문의가 오면 추측하지 않고 기록을 보고 어디가 느린지 짚을 수 있습니다.
   - 기록 위치: %LOCALAPPDATA%\B2B_logs
     (프로그램을 다시 켜면 지워지니, 문제가 생긴 직후에 복사해 주세요)

[ 알아 두시면 좋은 것 ]
────────────────────────────────────────────────────

● 보안(DRM)이 걸린 파일은 많이 느립니다
   - 사내 문서 중에 보안이 안 풀린 채로 올라오는 파일이 있습니다.
     이런 파일은 엑셀이 직접 열어서 보안을 풀어야 해서, 작은 파일도 10초 넘게 걸립니다.
   - 올리기 전에 보안 해제를 하시면 그만큼 빨라집니다.
   - 겉보기로는 구분이 안 되니, 유독 느린 파일이 있으면 보안 해제를 확인해 보세요.

● 단축키 정리
        화면 녹화     →   F10   (누를 때마다 시작 / 정지)
        AI 도움       →   F11   또는 화면 맨 위 [✦ AI 도움] 버튼
        새로고침      →   F5    또는 화면 맨 위 [🔄 새로고침] 버튼
        개발자 설정   →   F9

그래도 해결이 안 되면 %LOCALAPPDATA%\B2B_logs 폴더와 함께 알려 주세요.
