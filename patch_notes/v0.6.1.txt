B2B 빌링 Agent — 업데이트 안내 (0.6.1)
====================================================

[ 고친 점 / 바뀐 점 ]
----------------------------------------------------

● 전체실행이 중간에 실패했을 때 '적용됨' 표시가 실제와 정확히 일치해요
   - 예: 6단계 스킬 실행 중 5단계에서 오류가 나면 1~4단계가 '적용됨'으로 표시되는데,
     여러 파일을 다루는 스킬에서는 실제 Excel 에 반영이 안 돼 있는 경우가 있었습니다
     (실패 시 되돌리기가 오류 난 파일 하나만 복원하면서 표시는 전부 '적용됨'으로 남던 문제).
   - 이제 실패 시점의 '관여 파일 전체' 상태를 저장해 두었다가 모든 파일을 그 상태로 복원하고,
     복원이 전 파일에서 확인된 경우에만 '적용됨'을 표시합니다. 복원이 안 된 경우에는
     '적용됨'을 표시하지 않아, 화면과 실제 Excel 이 어긋나지 않습니다.
   - 이전 실행의 낡은 복원 지점이 남아 잘못 복원되던 경우도 함께 막았습니다.

● 단계마다 '스킬명' 버튼이 생겼어요
   - 단계 이름을 더블클릭으로 바꾸려면 여러 번 시도해야 열리는 경우가 있었습니다
     (실행 중 화면 갱신이 끼어들면 더블클릭 인식이 끊기고, 열린 입력칸도 사라지던 문제).
   - 이제 단계 이름 옆의 '스킬명' 버튼을 한 번만 누르면 바로 이름을 고칠 수 있고,
     실행 중 화면이 갱신돼도 입력칸이 닫히지 않습니다.
     (오른쪽의 ✎ 버튼은 기존처럼 '스킬 코드 수정'입니다. 더블클릭도 계속 동작합니다.)

● 스킬을 저장하면 '원래 이름' 그대로 저장돼요 (수정 후 저장한 스킬이 재사용 불가해지던 문제)
   - 파일을 연결(파일확인)해서 실행한 뒤 스킬을 수정하고 저장하면, 저장된 스킬에 그때 사용한
     파일명(날짜 포함)과 그 순간에만 유효한 내부 시트명이 통째로 박혀 버렸습니다.
   - 그 스킬을 다시 올리면 원래 이름과 박힌 이름이 둘 다 필요한 것처럼 잡혀 '파일확인'이
     갑자기 복잡해지고(필요 파일이 두 배로 늘어남), 다음 달 파일에는 쓸 수 없었습니다.
   - 이제 저장은 항상 원래(범용) 이름 기준으로 이뤄지고, 수정한 내용은 그대로 보존됩니다.
     실행이 끝난 뒤에도 스킬에 실행 당시 파일명이 남지 않습니다.

● '파일확인'에서 지정한 파일 연결이 유지되고, 생성기 수정 후 실행에도 적용돼요
   - 실행기에서 파일을 직접 골라 연결(파일확인)한 뒤, 전체실행 → '결과 편집하기' → 스킬 수정 →
     다시 실행하면 "워크북 '...' 이 열려 있지 않습니다" 오류가 나던 문제를 고쳤습니다.
   - 원인 두 가지를 함께 고쳤습니다.
     (1) 연결 기록이 지워짐: 스킬 실행으로 시트가 새로 생기거나(결과 편집하기) 스킬 코드를
         한 글자만 고쳐도 직접 지정한 파일 연결이 초기화됐습니다. 이제 유지됩니다.
         (다른 스킬을 불러오거나 파일을 새로 올리면 예전처럼 다시 확인합니다.)
     (2) 수정 후 실행에 연결이 안 쓰임: 파일 연결은 실행기 실행 버튼에서만 적용됐습니다.
         이제 스킬 수정·켜고끄기 후 재실행에도 같은 연결이 적용됩니다.
   - 특히 '도서/시내'처럼 사람만 구분할 수 있는 파일은 자동으로 못 고르므로, 직접 지정한 연결이
     유지되는 것이 중요합니다. 저장된 스킬 코드는 원래대로 보존됩니다.

● 피벗이 항상 '진짜 피벗테이블'로 만들어져요
   - 같은 피벗 명령인데 어떨 때는 진짜 피벗테이블(새로 고침 가능), 어떨 때는 값만 채운
     요약표가 만들어지던 문제가 있었습니다. 같은 피벗을 다시 만들면 2번째부터는 값 표로
     바뀌던 것이 원인이었습니다.
   - 이제 몇 번을 다시 만들어도 항상 진짜 피벗테이블입니다(같은 이름의 피벗 시트는 새로
     갱신됩니다). 만들 수 없는 경우에는 값 표로 몰래 바꾸지 않고 이유를 알려드립니다.

● 클릭이 두 번 실행되거나, Ctrl+클릭 다중선택이 안 되던 문제를 고쳤어요
   - 버튼을 조금 오래 누르고 있으면 같은 동작이 두 번 실행되는 경우가 있었습니다.
   - 시트 탭 등에서 Ctrl(또는 Shift)+클릭으로 여러 개를 고를 때 하나만 선택되던 문제,
     '값만' 같은 체크박스가 원격 환경에서 안 켜지던 문제를 고쳤습니다.
   - 키보드 Enter 로 누르는 버튼이나 화면 구분선(좌우 너비 조절) 드래그가 오작동하던 것도
     함께 고쳤습니다.

● '작업 중단'이 정상 작업을 성급히 끊어버리던 문제를 고쳤어요
   - 되돌리는 작업이 오래 걸릴 뿐인데도 10초가 지나면 무조건 Excel 을 강제 재시작해서,
     느린 PC 에서는 멀쩡한 작업까지 통째로 다시 시작되곤 했습니다.
   - 이제 '시간'이 아니라 '진행 여부'로 판단합니다. 진행 중이면 끝까지 기다리고, 정말로 멈춘
     경우에만 강제 중단합니다. (급할 때 '작업 중단'을 한 번 더 누르면 즉시 강제 중단됩니다.)
   - 강제 중단 뒤 스킬이 자동으로 다시 적용되지 못한 경우, 예전에는 화면만 '적용됨'으로 남아
     이후 계산이 조용히 틀릴 수 있었습니다. 이제 적용 표시를 정확히 풀고 안내합니다.

● 다른 달 파일을 이어 쓸 때 엉뚱한 파일에 실행되던 문제를 고쳤어요
   - 지난달·이번달 파일을 함께 올리면 실행기가 '먼저 올린 지난달 파일'을 조용히 골라
     실행하는 경우가 있었습니다. 이제 어느 것인지 확실하지 않으면 직접 고르도록 물어봅니다.
   - 월·날짜만 다른 파일을 자동으로 이어붙인 경우, 초록색 '정확 매칭'이 아니라
     '확인 필요(다른 달 추정)'로 표시해 한 번 확인하실 수 있게 했습니다.
   - 파일명에 들어간 거래처코드·지점번호(예: 500255, 지점 105)를 날짜로 착각해 서로 다른
     파일을 같은 파일로 취급하던 문제, 'hardcopy' 같은 이름 끝이 잘리던 문제도 고쳤습니다.

● 여러 파일을 다루는 스킬에서 시트가 중복으로 쌓이던 문제를 고쳤어요
   - 다른 파일로 시트를 복사하는 스킬을 '적용' 후 '전체실행' 하면 실행할 때마다
     '원가 (2)', '원가 (3)' 처럼 시트가 계속 늘어나는 경우가 있었습니다.
   - 단계를 끄거나 지우거나, 되돌리기(Ctrl+Z)를 했을 때 붙여넣은 시트가 안 지워지던 경우도
     함께 고쳤습니다.
   - 파일명에 괄호나 공백이 들어간 출력 파일(예: "output)_..." )로 시트를 복사하는 스킬은
     중간에 단계를 삽입하고 전체실행하면 시트가 또 추가되던 문제도 고쳤습니다.

● 복붙으로 만든 스킬이 실행기에서 '알 수 없는 파일'을 요구하던 문제를 고쳤어요
   - 복사/붙여넣기 캡처로 만든 단계가 실제 파일 이름 대신 내부 임시 이름(excel_open_... )을
     기억해 버려서, 필요한 파일을 모두 올려도 '파일 선택 필요' 2개가 사라지지 않고
     실행도 실패할 수 있었습니다.
   - 이제 캡처하는 시점부터 실제 파일 이름으로 저장되고, 예전에 저장해 둔 스킬도
     불러올 때 자동으로 고쳐집니다(파일확인 목록이 정상으로 돌아옵니다).

● '조건에 맞으면 처리'하는 스킬이 해당사항 없는 파일에서 오류로 멈추던 문제를 고쳤어요
   - 예: '소계 행이 있으면 삭제' 단계는 이번 달 파일에 소계가 아예 없으면 할 일이 없는 게
     정상인데, "아무 변경도 없습니다" 오류로 전체실행이 그 단계에서 중단됐습니다.
   - 이제 대상 시트의 데이터를 실제로 읽고 확인한 뒤의 '변경 없음'은 정상 완료로 처리합니다.
     (엉뚱한 시트를 읽어 아무것도 못 한 경우는 지금처럼 오류로 알려드립니다.)

● 파일확인에서 '스킬이 찾는 파일' 이름 앞부분이 잘려 보이던 문제를 고쳤어요
   - 파일명이 input)/output) 등으로 시작하고 중간에 공백(날짜·시각)이 있으면,
     마지막 조각(예: "10_02_56_DSMC_260713.xlsx")만 표시되던 문제입니다.
   - 표시만이 아니라 자동 매칭 점수에도 잘린 이름이 쓰였어서 함께 바로잡았습니다.

● 완료된 스킬을 수정해 재실행해도 결과에 반영되지 않을 수 있던 문제를 고쳤어요
   - '수정 직전 상태로 되돌리기'가 실패하면 수정된 코드가 실행되지 않았는데도
     '✓ 수정 적용됨'으로 표시돼, 옛 값 그대로인 산출물이 나갈 수 있었습니다.
     (특히 '빈 칸인 행만 채우기'류 단계는 이전 실행이 채워 둔 값이 남아 있으면
      할 일이 없다고 판단해 조용히 지나가므로 증상이 눈에 띄지 않았습니다.)
   - 이제 되돌리기에 실패하면 스킬 전체를 처음부터 다시 적용해 수정본을 반드시 반영하고,
     되돌릴 지점(스냅샷)이 불완전하면 빠른 이어실행 대신 전체 재적용을 택합니다.

● 프로그램을 최소화해도 Excel 창이 화면에 따로 남던 문제를 고쳤어요
   - 파일 업로드 직후나 '결과 편집하기' 직후에 최소화하면, 뒤늦게 열리던 Excel 창이
     프로그램 없이 화면에 혼자 떠 있는 경우가 있었습니다(위치 갱신이 창을 되띄우는 경우 포함).
   - 이제 최소화 중에는 어떤 경로로도 Excel 창이 화면에 나타나지 않고,
     창을 다시 열면 원래 자리(오른쪽 화면)로 함께 복귀합니다.

● 프로그램 종료 시 Excel 이 백그라운드에 남던 경우를 줄였어요
   - 파일이 여러 개 열려 있거나 정리가 오래 걸리면 보이지 않는 Excel 이 남을 수 있었습니다.
   - 정리를 끝까지 기다린 뒤 종료하도록 고쳤습니다(창은 즉시 사라져 체감은 그대로입니다).
