# v0.5.10 오늘 수정 전체 스모크 시나리오

## 테스트 파일

```text
test_data/v0510_today_full_smoke.xlsx
```

권장 방식:

- 각 시나리오는 가능하면 파일을 새로 업로드하거나 초기화 후 실행한다.
- 같은 파일에서 여러 시나리오를 연속 실행하면 앞 시나리오가 값을 바꿔 기대 결과가 달라질 수 있다.
- 실패로 봐야 하는 공통 증상: 적용 버튼을 눌렀는데 원치 않는 `(VBA 전환 재생성)`이 뜸, 강제적용 버튼이 뜸, 전체실행 후 파이프라인 상태와 엑셀 결과가 서로 안 맞음.

---

## 1. 월정보 +1, 기본 라우팅(ctx 우선)

목적:

- 엔진을 명시하지 않은 작은 범위 텍스트 변경은 Python COM/ctx로 처리 가능한지 확인한다.
- 월 텍스트가 한 셀 안에 여러 번 있어도 모두 바뀌는지 확인한다.

프롬프트:

```text
선택 범위: @범위[v0510_today_full_smoke.xlsx/2026년!B337:D337] 월 정보를 +1 변경해줘
```

기대:

- 가능하면 `def transform(ctx):` 형태로 생성된다.
- B337:D337 결과가 B339:D339 기대값과 일치한다.
- `import re`가 생성되더라도 Python 안전 재생성으로 고쳐져야 하며, VBA로 자동 전환되면 실패다.

---

## 2. 월정보 +1, 사용자가 Python을 명시한 경우

목적:

- 에러복구나 일반 채팅에서 사용자가 `python으로`라고 명시하면 VBA fallback으로 넘어가지 않는지 확인한다.

프롬프트:

```text
선택 범위: @범위[v0510_today_full_smoke.xlsx/2026년!B337:D337] 월 정보를 +1 변경해줘, python으로
```

기대:

- 최종 코드는 `def transform(ctx):`로 유지된다.
- 적용 전 안전 재생성이 필요해도 `(VBA 전환 재생성)`이 뜨면 실패다.
- Python 코드에 `import re`가 있으면 `import` 없는 코드로 다시 생성되는 것이 정상이다.

에러복구 확인:

1. 어떤 스텝이 실패한 뒤 `에러 복구 시도`를 누른다.
2. 추가 입력란에 아래처럼 쓴다.

```text
python으로 짜줘
```

기대:

- 복구 결과가 Python COM 코드로 유지된다.
- 적용 버튼을 눌렀을 때 자동으로 VBA로 바뀌면 실패다.

---

## 3. 월정보 +1, 사용자가 VBA를 명시한 경우

목적:

- VBA에서 `CreateObject("VBScript.RegExp")`가 안전검사 오탐으로 막히지 않는지 확인한다.
- `WScript.Shell` 같은 위험 객체 차단은 유지되어야 한다.

프롬프트:

```text
선택 범위: @범위[v0510_today_full_smoke.xlsx/2026년!B337:D337] 월 정보를 +1 변경해줘, vba로
```

기대:

- VBA 코드가 생성된다.
- `CreateObject("VBScript.RegExp")`가 들어가도 강제적용 버튼이 뜨면 실패다.
- 적용 후 B337:D337 결과가 B339:D339 기대값과 일치한다.

---

## 4. 한글 시트명 정확 참조

목적:

- VBA가 `통합인터넷(국제)`를 `통합internet(국제)`처럼 영문화하지 않는지 확인한다.

프롬프트:

```text
선택 범위: @범위[v0510_today_full_smoke.xlsx/통합인터넷(국제)!I2:N8] 데이터를 지워줘, vba로
```

기대:

- 코드 안의 실제 시트 접근 구문이 반드시 `"통합인터넷(국제)"` 그대로여야 한다.
- `"통합internet(국제)"`처럼 바뀐 코드가 나오면 안전 재생성이 떠야 한다.
- 적용 후 `통합인터넷(국제)` 시트의 I2:N8 값이 비워진다.

## 5. 조건부 행 삭제는 VBA 일괄 삭제로 라우팅

목적:

- `20260403 이전이면 행 삭제` 같은 조건부 행 삭제가 Python COM으로 가지 않는지 확인한다.
- VBA가 행을 하나씩 `Rows(...).Delete` 반복하지 않고 보조열+AutoFilter 방식으로 생성되는지 확인한다.

프롬프트:

```text
선택 범위: @범위[v0510_today_full_smoke.xlsx/조건삭제!F:F] 20260403 이전이면 해당 행 삭제해줘
```

기대:

- `def transform(ctx):`가 아니라 VBA로 생성된다.
- 큰 파일 대응을 위해 보조열+AutoFilter 또는 일괄 삭제 방식이어야 한다.
- 적용 후 `조건삭제` 시트에서 `20260401`, `20260402`, `2026-03-31` 행은 없어지고 `20260403`, `20260404`, `2026-04-30` 행은 남아야 한다.
- 삭제 대상이 없어도 오류를 내지 않는 코드면 더 좋다.

## 6. 긴 숫자 보존 필터 후 새 시트 생성

목적:

- 긴 ID가 필터 후 새 시트로 옮겨질 때 과학표기나 15자리 손실로 망가지지 않는지 확인한다.

프롬프트:

```text
선택 범위: @범위[v0510_today_full_smoke.xlsx/긴숫자원본!F:F] 중에 2020년에 해당하는 행들만 필터링해서 새 시트에 넣어줘
```

기대:

- 새 시트가 생성되고 2020년 행만 복사된다.
- `긴ID` 값이 아래처럼 원문 그대로 남아야 한다.

```text
89033023311240000000012140033938
01001234567890123456789012345678
00000000000000000000000000000001
```

실패 예:

- `8.9033E+31`처럼 보임.
- 긴 ID들이 전부 같은 과학표기 값으로 취급되어 나중에 중복 제거가 잘못됨.

## 7. 복붙 캡처, 값만 체크박스, 스킬 삭제/ON-OFF

목적:

- 복붙 캡처 스킬이 파이프라인에 들어간 뒤 삭제해도 이전 단계 결과가 날아가지 않는지 확인한다.
- ON/OFF가 삭제 이후에도 정상 동작하는지 확인한다.
- 값만 체크박스가 켜진 상태에서는 값만 붙여넣는지 확인한다.

절차:

1. `복붙_파이프라인` 시트에서 A3:D6을 복사한다.
2. 같은 시트 F3을 선택하고 붙여넣는다.
3. 프로그램에서 `복붙 캡처` 버튼을 누른다.
4. 생성된 스킬을 적용한다.
5. 체크박스 `값만`을 켠 뒤 같은 복붙 캡처를 한 번 더 만든다.
6. 파이프라인에서 마지막 복붙 스킬을 삭제한다.
7. 이전 스킬들의 ON/OFF를 눌러본다.

기대:

- 값만 체크가 꺼져 있으면 수식/서식이 보존된다.
- 값만 체크가 켜져 있으면 값만 붙는다.
- 마지막 스킬 삭제 후에도 이전 단계 결과가 갑자기 사라지면 실패다.
- 삭제된 스킬이 목록에 남아 있거나 ON/OFF가 먹지 않으면 실패다.

## 8. 스킬 불러오기 누락 의존성 후보 생성

목적:

- 저장된 파이프라인에 필요한 중간 시트 생성 단계가 빠졌지만, 대화 기록에는 그 코드가 있는 경우 자동으로 후보를 보여주는지 확인한다.

이 테스트는 일부러 파이프라인을 깨는 절차다.

절차:

1. 새로 파일을 업로드한다.
2. 아래 요청을 보낸 뒤 적용한다.

```text
v0510_today_full_smoke.xlsx에 새 시트 피벗_결과를 만들어줘
```

3. 아래 요청을 보낸 뒤 적용한다.

```text
피벗_결과 시트 A1에 "OK"라고 입력해줘
```

4. 파이프라인에서 1번 스텝, 즉 `피벗_결과` 시트 생성 스텝만 삭제한다.
5. 스킬 저장을 누른다.
6. 초기화 후 방금 저장한 스킬을 불러온다.
7. 전체실행을 누른다.

기대:

- 2번 스텝이 `피벗_결과` 시트를 못 찾아 실패한다.
- 단순히 막히는 것이 아니라, 대화 기록에서 `피벗_결과` 시트 생성 후보를 찾아 보여줘야 한다.
- 삽입 버튼을 누르면 실패 스텝 앞 위치가 제안되어야 한다.

---

## 9. 강제 진행 의도 확인

목적:

- 사용자가 `그냥 해`, `안전검사 무시하고 해`처럼 명시하면 하드 위험이 아닌 정적 가드는 우회 가능한지 확인한다.
- 단, `Shell`, `Workbooks.Open`, `Save/Close`, 위험 `CreateObject` 같은 하드 위험은 계속 막혀야 한다.

예시 추가 입력:

```text
안전검사 무시하고 그냥 해줘
```

기대:

- 소프트 가드는 강제 적용 버튼으로 진행 가능하다.
- 하드 위험은 여전히 차단된다.
