# v0.5.10 VBA 숨김해제 no-op 회귀 테스트

## 목적

VBA 숨김/숨김해제 작업이 실제로 적용됐는데도 프로그램이 아래 오류를 띄우며 스킬 생성을 막던 문제를 재현/검증한다.

```text
VBA 가 실행됐지만 워크북에 아무 변경도 없습니다.
'적용됨'으로 잘못 보고되지 않도록 실패로 처리했습니다.
```

이 테스트는 `Rows(...).Hidden = False`, `Columns(...).Hidden = False` 같은 구조 상태 변경이 셀 값/수식 fingerprint에 잡히지 않아도 성공 처리되는지 확인한다.

## 테스트 파일

파일:

```text
test_data/v0510_vba_hidden_noop.xlsx
```

초기 상태:

- `VIEW` 시트의 `3:5` 행은 숨김 상태다.
- `VIEW` 시트의 `B:C` 열은 숨김 상태다.
- `README` 시트에는 테스트 설명이 들어 있다.

## 시나리오 1: 행 숨김해제

1. 프로그램에 `v0510_vba_hidden_noop.xlsx`를 입력 파일로 업로드한다.
2. 아래 프롬프트를 보낸다.
3. 생성된 스킬을 적용한다.

```text
선택 범위: @범위[v0510_vba_hidden_noop.xlsx/VIEW!3:5] 숨기기 취소 해줘(vba로)
```

기대 결과:

- 오류 없이 적용된다.
- 스킬 파이프라인에 단계가 추가된다.
- `VIEW` 시트의 3~5행이 보인다.
- "워크북에 아무 변경도 없습니다" 오류가 뜨지 않는다.

## 시나리오 2: 같은 행 숨김해제 재적용

시나리오 1을 적용한 뒤, 같은 프롬프트를 다시 보낸다.

```text
선택 범위: @범위[v0510_vba_hidden_noop.xlsx/VIEW!3:5] 숨기기 취소 해줘(vba로)
```

기대 결과:

- 이미 3~5행이 보이는 상태여도 오류 없이 적용된다.
- 스킬 파이프라인에 단계가 추가된다.
- "아무 변경 없음" 오류 때문에 스킬 생성이 막히지 않는다.

이 단계가 핵심 no-op 회귀 테스트다.

## 시나리오 3: 열 숨김해제

초기 파일을 다시 업로드하거나 초기화한 뒤 아래 프롬프트를 보낸다.

```text
선택 범위: @범위[v0510_vba_hidden_noop.xlsx/VIEW!B:C] 숨기기 취소 해줘(vba로)
```

기대 결과:

- 오류 없이 적용된다.
- `VIEW` 시트의 B~C열이 보인다.
- 같은 프롬프트를 한 번 더 적용해도 "아무 변경 없음" 오류가 뜨지 않는다.

## 실패로 봐야 하는 경우

아래 중 하나라도 발생하면 회귀다.

- VBA는 실행됐다고 보이는데 스킬 카드가 생성되지 않는다.
- "VBA 가 실행됐지만 워크북에 아무 변경도 없습니다" 오류가 뜬다.
- 에러 복구로 넘어가며 사용자가 다시 설명해야 한다.
- 강제 적용을 눌러야만 넘어간다.

## 관련 스모크 테스트

```powershell
python test_runs\_test_vba_hidden_noop.py
```

기대 출력:

```text

```
