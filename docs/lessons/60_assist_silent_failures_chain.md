# 60. AI 도움이 조용히 실패하던 네 가지 — 답이 비고, 멈추고, 도망가고, 2배로 틀렸다

날짜: 2026-09-09 / 버전: 0.8.4

교안 실습을 그대로 따라가다 나온 실측 네 건. 전부 오류가 아니라 **그럴듯하게 잘못된 응답**이라
사용자가 "?" 를 치거나 이상함을 눈치채야만 드러났다.

---

## ① 답이 "이유는 이래요." 하고 비었다

실패한 단계를 진단시켰더니 본문이 통째로 사라진 답이 나왔다.

**원인**: 응답에서 '프롬프트 되풀이'를 걷어내는 `assistStripPromptEcho` 의 소스에 `tail` 전체가
들어가 있었다. `tail` 에는 **도구 결과(`[도구 결과 step.error] <tool-data>…`)** 도 들어 있다.
모델이 오류 메시지를 인용해 설명하자, 그 문장이 "에코"로 판정돼 지워졌다.

**수정**: 소스를 셋으로 나눴다 — 시스템 프롬프트·내부 재촉문은 엄격(짧은 문장까지 제거),
사용자 메시지는 긴 문단(≥30자)만, **도구 결과와 모델의 이전 답은 소스에서 제외**.
테스트에서 옛 구성으로 돌리면 인용이 사라지는 것까지 대조로 잠갔다.

---

## ② "…볼게요." 하고 멈췄다 (두 번 재발)

- 1차: *"매출 원본의 총합을 읽어서 맞춰 볼게요. 원본은 금액 열이에요."* → 멈춤
- 2차(1차 수정 후): *"먼저 1단계 코드를 볼게요."* → 또 멈춤

**원인**: 예고문 감지가 (a) **마지막 문장만** 봤고, (b) 동사 **허용목록**(찾/확인/조회/읽/…)에
기대는 방식이었다. (a) 는 예고 뒤에 짧은 부연이 한 문장 붙으면 놓치고, (b) 는 '보다'처럼
빠진 동사가 나올 때마다 구멍이 다시 난다.

**수정**: (a) 뒤따르는 문장이 '결과가 아닌 짧은 부연'(≤50자·숫자 없음·결과 어미 없음)이면
앞 문장까지 검사. (b) **허용목록을 버리고** 약속 어미로 끝나는 짧은 문장은 인사말
(필요하면/감사/수고/좋은 하루…)만 빼고 전부 예고로 본다. 재촉은 최대 2회라 오탐 비용이 작다.
재촉이 발동하면 `assist.nudge` 트레이스를 남겨 다음 재발 때 바로 보이게 했다.

> 허용목록(allowlist)으로 자연어를 잡으려 하면 구멍이 계속 난다. **금지목록 + 넉넉한 기본값**이
> 낫다 — 특히 오탐 비용이 '한 번 더 물어보기' 수준일 때는.

---

## ③ 검산을 시켰더니 설계 채팅으로 도망갔다

*"회사별요약의 매출 합계가 매출 원본의 총합과 같은지 검산해줘"* → 답 대신
"미리보기 59행만 더한 값이라 확정할 수 없다"며 **핸드오프 카드**를 내밀었다.

**원인**: `data.query` 가 라이브 미리보기(`_live_preview_schema`, `max_rows=60`)만 계산했다.
1,200행 시트의 합계가 '최소값'으로만 나오니 모델은 정직하게 답을 유보한 것이다.

**수정**: 실제 행수(`dims.maxRow`)가 캐시보다 많으면 그 시트만 `preview-schema` 에
`maxRows`(단일 시트 한정, ≤20000)를 얹어 다시 읽는다. 캐시(`f.sheets`)에는 넣지 않는다 —
생성 프롬프트의 미리보기가 커지면 안 되기 때문.

---

## ④ 같은 검산에서 이번엔 "2배"라며 단계를 뒤졌다

전체 행을 읽게 고쳤더니, 이번엔 요약표 합계가 원본의 **정확히 2배**로 나왔고 모델이
*"어디서 2배가 됐는지 코드를 봐야 한다"* 며 스킬 단계를 열람하기 시작했다.

**원인**: 요약표 맨 아래 **`합계 / 평균` 행까지 더해서** 정확히 2배가 됐다.
사용자 지적이 정확했다 — *"이런 상황에서 단계를 볼 필요가 있나? 그냥 독립적으로 읽으면 되는 것"*.

**수정**:
- `data.query` 집계(sum/count/distinct/group\*)에서 요약 행(합계·소계·총계·누계·평균·`…계`·
  부가세/VAT·Total)을 **기본 제외**하고, 제외 개수·라벨을 결과 note 로 알려 준다.
  `includeSummaryRows=true` 로 예전 동작, `sample` 은 그대로 보여준다.
- 시스템 프롬프트에 `[검산·비교 질문]` 규칙 추가: **두 값을 각각 읽어 결론부터** 말하고,
  단계·코드 탐색은 "어디서 달라졌는지" 요청이 있을 때만. 값이 정확히 2배면 합계 행 중복부터 의심.

---

## 실제 앱으로 끝까지 돌려 확인했다

사용자 지시(*"추론하지말고 직접 테스트해봐"*)에 따라 격리 백엔드(포트 18091)를 띄우고
Playwright 로 교안 실습 파일 3개 업로드 → 5단계 스킬 로드 → 전체 적용 → AI 도움 질문까지
실제 LLM 으로 돌렸다:

```
data.query(매출 원본)  → 1,200행 전체 기준(잘림 없음)  sum=3,797,128,000
data.query(회사별요약) → 21행, 요약 행 1개 제외         sum=3,797,128,000
답(17초, 핸드오프 없음): "검산 결과 두 값이 정확히 일치합니다 … 차이: 0"
```

교안이 기대하는 값(3,797,128,000)과 일치. 이 하네스는
`test_runs/_e2e_assist_verify_live.py` 로 남겼다(수동 실행 — 별도 포트 백엔드 + LLM 키 필요).

## 배운 것

1. **필터는 자기가 무엇을 지우는지 알아야 한다.** "프롬프트 에코 제거"가 근거 인용을 먹은 건,
   필터 소스에 '데이터'와 '지시문'이 섞여 있었기 때문이다. 둘은 항상 분리해서 다뤄라.
2. **도구가 조용히 잘라 주면 모델은 정직하게 도망간다.** 60행만 준 게 잘못이지 모델 잘못이 아니다.
   집계 도구는 '전체'인지 '일부'인지를 값과 함께 반드시 알려야 한다.
3. **요약 행은 데이터가 아니다.** 표 열을 합칠 때 합계 행을 같이 더하면 정확히 2배가 나오고,
   그 숫자는 사람도 AI 도 "이상하다"고 오해한다. 집계 도구가 기본으로 걸러야 한다.
4. **문장 규칙은 금지목록으로.** 허용목록 방식은 재발이 예약돼 있다(②에서 두 번 겪었다).

관련: `registry.json` 의 `ASSIST-ECHO-STRIP-ATE-EVIDENCE` / `ASSIST-DANGLING-WITH-ASIDE` /
`ASSIST-DANGLING-VERB-ALLOWLIST` / `ASSIST-DATAQUERY-FULL-ROWS` / `ASSIST-VERIFY-SUMMARY-ROW-2X`.
