## 오늘 고친 것 요약

1. 0.5.7 기반으로 0.5.8 작업본을 분리하고 버전 표기를 0.5.8로 갱신했다.
2. 복사/붙여넣기 관련 안전 재생성 가드를 제거했다. 특히 사용자가 "값", "값만", "값으로 붙여넣기"라고 명시한 경우 수식 복사나 안전 재생성 차단이 발생하지 않도록 했다.
3. Python COM 프롬프트에서 값만 복사는 `ctx.copy()`가 아니라 `ctx.read()` + `ctx.write(..., overwrite_formulas=True)` 흐름으로 안내하도록 했다.
4. 피벗/유사 피벗, 복합 조건 행 처리, 시트 전체 교차 파일 복사는 자동으로 VBA 엔진에 라우팅되도록 했다.
5. 안전가드 실패 시 같은 엔진 재시도는 1회만 수행하고, 다시 실패하면 VBA로 전환 생성 후 자동 적용하도록 했다.
6. VBA 피벗/그룹 요약에서 `발신번호`, `전화번호`, `ID`, `코드` 같은 식별자는 `.Text`로 읽고 텍스트 서식으로 써서 선행 0이 사라지지 않도록 프롬프트를 보강했다.
7. A파일 시트 전체를 B파일 새 시트로 복사하는 `ctx.copy_sheet()` 교차 파일 복사를 보강했다. 대상 파일이 다른 Excel 인스턴스에 있거나 읽기 전용 동반 파일로 잡히는 경우를 처리한다.
8. Python COM 스킬과 VBA 스킬이 섞인 파이프라인도 전체 실행에서 같은 live Excel 계열 경로로 순서대로 실행되도록 확인/보강했다.
9. 여러 워크북이 열려 있을 때 VBA 임시 모듈을 주입한 워크북이 아닌 활성 워크북에서 매크로를 찾는 문제를 막기 위해 `Application.Run`을 워크북명으로 한정했다.
10. 시간→초 환산 VBA는 `01:02:03` 같은 콜론 텍스트, Excel 시간 시리얼, 이미 초 단위인 숫자를 모두 처리하도록 프롬프트와 정적 검사를 보강했다.
11. 피벗/그룹 요약 VBA는 `On Error Resume Next` 중복 제거, `Collection.Add` 오류 의존, `For Each` 문자열 제어 변수, 데이터 쓰기 뒤 텍스트 서식 적용을 정적 검사에서 잡도록 했다.
12. `tools/test_v058_direct.py`를 추가해 로컬 vLLM으로 스킬 코드를 생성하고 Excel COM에 직접 주입해 값 복사/조건문/피벗/시트 복사를 회귀 검증할 수 있게 했다.

## 시나리오 1. 값만 복사 + 수식 대상 덮어쓰기

목적:
사용자가 "값만"이라고 명시했을 때 수식을 복사하지 않고 계산 결과 값만 붙여넣으며, 대상 셀에 기존 수식이 있어도 안전 재생성에 막히지 않는지 확인한다.

프롬프트:

```text
input_v058_regression_source.xlsx의 값복사_수식원본 시트 D2:D6 값을 output_v058_regression_target.xlsx의 값복사_대상 시트 H2:H6에 값만 복사해서 붙여넣어. 수식은 복사하지 말고 계산된 값만 넣어.
```

기대 결과:

- 안전 재생성 가드가 뜨지 않는다.
- 생성 코드가 Python COM이면 `ctx.copy()`가 아니라 값 읽기/쓰기 흐름을 사용한다.
- `값복사_대상!H2:H6` 값이 `3600, 4000, 11000, 770, 9200`이 된다.
- `H2:H6`에는 `=ROW()*999` 같은 기존 수식이 남지 않고 값으로 바뀐다.
- H열의 노란 서식과 숫자 서식은 유지된다.

## 시나리오 2. 복합 조건 행 처리 자동 VBA 라우팅

목적:
조건문/행 단위 변환 요청이 Python COM에서 무거워지지 않도록 VBA로 자동 라우팅되는지 확인한다.

프롬프트:

```text
input_v058_regression_source.xlsx의 조건문_원본 시트에서 H열(서비스)이 "국제" 일 때 Q열(시간)을 초로 환산하여 S열 동일 행에 입력해줘.
```

기대 결과:

- 채팅 말풍선 상단에 `(VBA 라우팅)`이 표시된다.
- 생성 코드가 VBA 코드 블록이다.
- `조건문_원본!S2:S8` 결과가 다음과 같다.

| 행 | 기대값 |
| --- | --- |
| S2 | 3723 |
| S3 | 빈칸 |
| S4 | 45 |
| S5 | 빈칸 |
| S6 | 8110 |
| S7 | 빈칸 |
| S8 | 125 |

## 시나리오 3. VBA 피벗에서 발신번호 선행 0 보존

목적:
VBA 피벗/그룹 요약에서 발신번호가 숫자로 변환되어 앞자리 0이 사라지는 문제를 검증한다.

프롬프트:

```text
input_v058_regression_source.xlsx의 피벗_발신번호 시트에서 발신번호를 행으로, 호유형을 열로, 통화요금의 합계를 값으로 하는 유사 피벗을 새 시트 "피벗_결과"에 만들어줘. VBA로 해줘.
```

기대 결과:

- 생성 코드가 VBA다.
- 새 시트 `피벗_결과`가 생성된다.
- 첫 번째 열의 발신번호가 `010091645354`, `020020995203`, `010075250850`처럼 선행 0을 보존한다.
- 발신번호 열의 숫자 서식이 텍스트(`@`)로 잡히거나, 최소한 화면에 앞자리 0이 그대로 보인다.
- 호유형별 열에 통화요금 합계가 분리되어 들어간다.

## 시나리오 4. A파일 시트 전체를 B파일 새 시트로 복사

목적:
A파일에서 시트 전체를 복사해 B파일 새 시트로 붙여넣는 교차 파일 복사가 동작하는지 확인한다.

프롬프트:

```text
input_v058_regression_source.xlsx의 전체복사_원본 시트 전체를 output_v058_regression_target.xlsx에 새 시트 "전체복사_복사본"으로 복사해줘.
```

기대 결과:

- 자동 VBA 라우팅 또는 시트 전체 복사 전용 경로를 사용한다.
- `output_v058_regression_target.xlsx`에 `전체복사_복사본` 시트가 생긴다.
- `A1:D1` 병합, 보라색 제목 서식, 표 헤더 서식, 숫자 서식이 유지된다.
- `B6`, `D3:D6`의 수식이 유지된다.

## 시나리오 5. Python COM + VBA 혼합 전체 실행

목적:
파이프라인에 Python COM 스킬과 VBA 스킬이 섞여도 전체 실행이 호환되는지 확인한다.

절차:

1. 시나리오 1을 적용한다. 값만 복사 스킬은 Python COM으로 생성될 가능성이 높다.
2. 시나리오 2 또는 3을 적용한다. 이 스킬은 VBA로 생성되어야 한다.
3. 스킬 파이프라인에 Python 스킬과 VBA 스킬이 함께 있는지 확인한다.
4. `전체 실행` 버튼을 누른다.

기대 결과:

- JavaScript 실행기로 떨어지거나 "Python/VBA 혼합 불가"류 오류가 나지 않는다.
- 전체 실행이 live Excel 계열 경로에서 순서대로 실행된다.
- 시나리오 1의 값 복사 결과와 시나리오 2/3의 VBA 결과가 모두 유지된다.

## 시나리오 6. 안전가드 1회 재시도 후 VBA 우회

목적:
안전가드가 같은 엔진 재생성을 반복하지 않고, 1회 재시도 후에도 문제가 남으면 VBA로 전환되는지 확인한다.

주의:
이 테스트는 LLM 출력에 따라 재현성이 낮다. 아래 프롬프트는 일부러 위험한 Python 스타일을 유도하는 관찰용이다.

프롬프트:

```text
input_v058_regression_source.xlsx의 조건문_원본 시트에서 H열이 "국제"인 행마다 S열에 "테스트"라고 넣어줘. Python으로 하되 각 행마다 write_cell로 써줘.
```

기대 결과:

- Python 코드가 루프 안 `ctx.write_cell()` 반복으로 나오면 안전가드가 1회만 안전 재생성을 시도한다.
- 재생성 코드도 안전가드에 걸리면 `(VBA 전환 재생성)` 흐름으로 넘어간다.
- VBA 우회 코드가 안전검사를 통과하면 자동 적용된다.
- VBA 우회 코드까지 안전하지 않으면 추가 재시도 없이 차단 안내가 뜬다.
