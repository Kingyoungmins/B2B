# 54. 판정은 이름이 아니라 내용으로, 실패는 무음이 아니라 로그로 (2026-08-24)

## 사건 셋 (모두 같은 날 실측 제보)

### ① 사내 DRM 문서 미인식 — "서버 로그에 아무것도 안 뜨고 그냥 열림"
- AIP(표준 OOXML 암호화)는 인식되는데 사내 DRM 은 통과. 원인: bool checker 가
  `EncryptedPackage` 스트림만 봤다 — 사내 DRM 의 OLE 래퍼(자체 스트림)는 "구형 .xls 평문"
  취급으로 **로그 한 줄 없이** 통과했고, 마커/재암호화 게이트가 안 걸려 산출물이 평문으로 샜다.
- 1차 수정(확장자 보정: OLE 인데 .xlsx 면 의심)은 코드리뷰가 반증: **DRM 이 원본 이름(.xls)을
  보존하면 도로 뚫린다.** 이름은 신뢰 경계 밖이다.
- 최종: OLE 디렉터리 스트림 **내용** 3상 판정(`_ole_office_verdict`):
  `EncryptedPackage`=encrypted / 구형 본문 스트림(Workbook·Book·WordDocument…)=plain /
  둘 다 아님=unknown→Gateway 문의(-200 이 최종 판정). 기존 FAT 체인 워크 재사용, 추가 I/O 0.
- 교훈: **화이트리스트(확장자·이름)로 보안 판정을 좁히면, 공격면이 그 리스트의 여집합이 된다.
  판정 근거는 파일이 스스로 증명하는 것(스트림 구성)이어야 한다.**

### ② 빠른 삭제 후 회색 화면 — "탭을 다시 눌러야 보임"
- `/api/excel/replace` 재오픈 직후의 show-only 가 새 SDI 프레임 준비 전에 도착해 무산.
  호출부가 반환값을 버리고 예외를 삼켜 **실패했다는 사실 자체가 어디에도 없었다.**
  탭 클릭(=show-only 재전송)이 즉시 살린 것이 진단의 결정적 근거(17:39:18 무산→17:39:24 복구).
- 수정: 적용 잠금 해제 후 같은 show-only 1회 재전송 + 결과를 `mirror.replace.reshow` 로 기록.
  리뷰 반영: uiClickGuard 승계, applying 은 취소 대신 연기(최대 2회), shown=false 재시도 1회.
- 미적용 형제 경로(runner 결과 반영·녹화 취소/재현·stop 복구·refreshExcelMirrorForFileId)는
  같은 무산 가능성이 남아 있다 — 다음 회색 제보가 그쪽이면 이 부품을 옮겨 붙일 것.
  (미러 스왐프 교훈대로 한 번에 전부 건드리지 않고, 제보된 경로만 고쳤다.)

### ③ 업로드 후 선택 미기록 — 계측 사각
- 선택 폴의 무산 지점(빈 주소/탭 불일치/muted/quiet/세션 미확립)이 전부 무음이라 로그로 특정
  불가 → 게이트 **전환 시에만** 1줄 트레이스(`mirror.selection.gate`, excelId 별 키).
  550ms 폴마다 찍으면 트레이스 락 경합(교훈 53)이라 전환 감지가 필수.

## 공통 교훈
1. **조용한 통과/조용한 실패가 가장 비싸다.** 보안 게이트든 화면 표시든, "아무 일도 안 한" 경로에
   흔적이 없으면 제보가 와도 특정할 수 없다. 판정·무산에는 사유를 갈라 로그를 남긴다
   (단, 폴링 경로는 전환 시에만 — 로그 자체가 병목이 되면 안 된다).
2. **진단 로그는 상태를 바꾸기 '전'의 사실을 찍어야 한다.** 해제 후 sniff 를 읽으면 released 건이
   전부 zip 으로 찍혀 도착 형태를 잃는다(리뷰 지적으로 교정).
3. registry 체크는 규격(`[kind, rel]` 2튜플, kind=node/python/com/marker)을 지킬 것 — 잘못된
   3항 인라인 체크 하나가 recheck 전체를 죽이고 있었다. 저장은 `save_registry` 와 같은
   직렬화(indent=2 + 개행)로 — 다른 포맷으로 쓰면 7천 줄 재포맷 diff 가 실변경을 묻는다.
