# 48. AI 도움이 자기 앱 용어("오류 후 보류")를 몰라 엑셀 미스터리 취급 + 도구를 ```python 으로 호출

## 증상 (2026-08-03 사용자 제보 — "개멍청하네")
- 사용자: "왜 오류후보류라고 떴어" → AI 도움이 **앱 상태칩 문구**를 엑셀 데이터 검증/조건부
  서식/VBA 셀 값으로 추측하는 일반론만 늘어놓음(도구 미사용). 원인 추적 실패.
- "아니 스텝 분석해야지 너가" → 모델이 ```python\nstep.error()\n``` 코드블록을 출력.
  이건 액션 블록(JSON)이 아니라서 **실행되지 않고 코드 원문이 사용자에게 그대로 노출**("??").

## 원인
1. **그라운딩 공백**: 시스템 프롬프트에 앱이 그리는 단계 상태칩 어휘(적용됨/보류/오류 후 보류/
   자동 복구 후 보류/수정됨·미적용/중단됨·미적용 등)가 없었다. 사용자가 가장 자연스럽게 묻는
   질문("화면에 뜬 문구 왜 떠?")에 앱 자신의 UI 어휘로 답할 근거가 없어 엑셀 일반론으로 빠짐.
   ("오류 후 보류" = pipeline.js 전체실행 실패 시 체크포인트 복원 후 pendingLabel)
2. **호출 형식 위반 무방비**: assistParseAction 은 JSON 액션 블록만 파싱. 모델이
   ```python tool() 형태로 "호출"하면 파싱 실패 → final 강등 → 코드 원문 노출.

## 수정 (0.7.1 워킹트리)
- assist-core.js 프롬프트: **"앱 화면 용어(단계 상태칩)" 사전 섹션** 추가 — 각 칩의 뜻 +
  "이 문구를 엑셀 셀/서식으로 추측 금지" + 정답 순서(뜻 설명 → step.error 즉시 조회 → 다음 행동).
  응답 규약에 "```python 코드블록은 호출이 아니다(실행 안 됨) — 액션 블록만" 명시.
- assist-guard.js assistParseAction: JSON 파싱 전부 실패 시, 응답이 사실상 **인자 없는 도구 호출
  하나뿐이고 그 이름이 ASSIST_TOOLS 에 등록돼 있으면** {action:"tool"} 로 구제(짧은 응답 한정,
  설명문 속 예시 오인 방지). block 으로 매치 원문을 걷어 본문 노출도 막음.

## 교훈
- 인앱 도우미의 1순위 그라운딩은 **그 앱 자신의 화면 어휘**다. 사용자는 화면에 보이는 문구
  그대로 묻는다 — 상태칩/버튼/토스트 문구가 프롬프트에 없으면 가장 흔한 질문부터 오답.
- LLM 도구 호출은 "지시한 형식"만 오는 게 아니다 — 흔한 위반형(코드블록 호출)은 파서에서 구제.

## 후속 전수 감사 (같은 날, 서브에이전트 2방향 + 직접 점검)
같은 계열 구멍을 도구 커버리지/오케스트레이터 경로까지 전수 조사해 추가 수정:
- **setStepEnabled 카드가 스위치 모델 우회**(高): enabled 플래그만 직접 뒤집어 '꺼졌는데 결과에
  남음' 유령 상태 재생산 → handlePipelineStepToggle 단일 경로로 변경 + 카드 문구를 실제 동작대로.
  ON 비동기 실패 시 거짓 성공 방지(정착 후 상태 대조 → toast+팝업 통지). 프롬프트에 "OFF 는 그
  단계부터 끝까지 보류" 명시(중간 한 단계만 스킵 불가).
- **Python 위험코드 게이트 누락**(高): VBA 만 vbaStaticSafetyFailures 를 걸고 Python 교체 코드는
  무검사 통과 + 승인 '전' 격리 검증이 실행까지 함 → 기존 pythonComStaticSafetyFailures 를 두
  게이트(_assistGateReplacementCode·인라인)에 대칭 적용.
- **파일확인 매핑/녹화 상태 조회 불가**(高): 어떤 도구도 state.runnerMappings·녹화 플래그를 안 읽음
  → app.state 에 runnerMappings(요구키→파일/시트/userSet)·runnerMappingRunActive·recordingActive 노출.
- 배치(일괄 치환) 카드의 "전체실행하세요" 문구(생성기에 그 버튼 없음) → 스위치 안내로 교정.
  배치 자동 OFF 는 사용자가 이전에 '그대로 둬'로 결정 — 유령상태 근거가 새로 나와 재결정 대상.
- 컨텍스트 축출(tail 48K) 시 seenCalls 미정리 → 축출된 결과 재조회를 반복차단이 막아 모델이
  데이터 없이 강제 final → 축출 시 seenCalls.clear() (중복은 도구 상한 7회가 어차피 캡).
- result.summary '기록 없음'을 미실행/실패로 뭉개던 문구, truncated 값 확정 발화, 빈 기록=성공
  오독 → 반환 note + 프롬프트 읽기규칙으로 교정. no-op 토글/배치 성공 전용 카드 문구 추가.
