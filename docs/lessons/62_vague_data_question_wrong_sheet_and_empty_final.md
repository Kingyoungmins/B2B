# 62. "마진율 제일 적은거 3개" — 시트명 없는 질문에 AI 도움이 흔들린다(파일 없음·3위 오답·빈 답)

날짜: 2026-09-10 / 버전: 0.8.4

## 제보

사내 PC(ixi Qwen3.6-27B)에서 "마진율 제일 적은거 3개 뽑아달라" 하니 **"파일이 없다"며 못 찾음**.
로그가 없는 환경이라 개발망(Qwen3.8-27B)에서 같은 질문을 실제 앱에 반복해 던져 재현했다.

## 재현 — 같은 질문 3회, 세 가지 다른 실패

| 회차 | 도구 호출 | 결과 |
|---|---|---|
| 1 | `data.query(sheet="Sheet1")` → unknown_sheet → `sheet.headers` → 회사별요약 읽음 | **정답** (오리진네트 21 · 네오링크 23 · 메이저텔레콤 24) |
| 2 | 원본 매출/원가 시트를 뒤짐, `groupBy:["회사명","상품"]` 2회 헛발 | **포기**: "두 파일의 행이 어긋나서 이 도우미로는 짝짓기가 안 됐어요" |
| 3 | 원본 두 시트를 각각 groupSum 후 머릿속에서 나눗셈 | **3위 오답**(테크커넥트 26% — 24%·25% 두 회사를 건너뜀) |

핵심: **출력 파일 `회사별요약` 시트에 이미 '마진율' 열이 있는데 모델이 그걸 모른다.** 시스템 프롬프트 그라운딩 팩트에는
파일 이름만 있었고 시트·열 정보가 없었다. 그래서 "Sheet1"을 추측하거나 원본을 뒤졌다.
사용자의 "파일이 없다"는 여기에 더해 **도구의 파일 인자가 정확 일치만 통과**(확장자 없이·시트명을 파일 자리에·이름 일부 →
`unknown_file`)해서, 약한 모델이 그 오류를 그대로 사용자에게 옮긴 것이다.

## 수정 1 — 찾게 하기

- 그라운딩 팩트에 **파일별 시트(열 이름)** 를 싣는다: `output_청구서.xlsx — 시트: 회사별요약(회사명,매출,원가,마진,마진율) | …`
- `columns.find(열 이름)` 도구: 그 열이 있는 파일/시트/열문자를 전 파일에서 찾는다(정확 일치·출력 시트 우선).
- `_assistResolveFile / _assistResolveSheet`: 확장자·대소문자·일부 일치·"시트명을 파일로" 를 유일할 때만 보정.
  모호하면 고치지 않고 `available` 을 돌려준다(엉뚱한 파일을 읽는 것보다 낫다). `data.query`·`sheet.headers`·`data.read` 공용.
- `groupBy` 배열(복합 키), `schema.summary` 에 `headersBySheet`.

결과: 5회 모두 첫 호출부터 `output_청구서.xlsx / 회사별요약` 을 읽었다. 그런데 **2회는 3위를 또 틀렸다**(미래통신 25%).

## 수정 2 — 정렬은 도구가

모델은 `groupSum topN`(내림차순뿐)으로 안 되니 표 21행을 `data.read` 로 읽고 **눈으로 골랐다**. LLM 은 20개 숫자를
정렬하는 일을 못 믿을 만큼 자주 틀린다. `data.query op=rank(column, order=asc|desc, topN, labelColumn?)` 를 추가하고
(별칭 bottom/lowest/min → asc, top/highest/max → desc), 프롬프트에 "순위·최저·최고는 rank 로 받아 그 순서 그대로 답하라,
표를 읽고 눈으로 고르지 마라"를 넣었다. `sample` 은 열 목록을 콤마로 넘겨도(3회 헛발) 통과.

결과: 6회 모두 `rank(order=asc, topN=3)` 한 방 — 그런데 **1회는 답이 비었다**.

## 수정 3 — 본문 없는 final

원시 응답을 잡아 보니 도구 결과(정답)를 받은 직후 모델이 `{"action":"final","args":{}}` 만 보냈다. 루프는 이걸
"응답을 정리하지 못했습니다. 같은 질문을 다시 보내 주세요." 로 내보냈다 — 근거를 손에 쥔 채 빈 답을 준 셈.
`visible/salvaged/rawShown` 이 모두 비고 `parsed.parsed` 면 **1회 재촉**("본문 없는 final 은 답이 아니다. 받은 도구 결과의
rows 순서 그대로 본문을 써서 다시 보내라")하고, 그래도 비면 종전 안내로 끝낸다(무한 루프 상한 1).
LLM 을 각본대로 모의(route)해 실제 루프에서 결정적으로 검증했다(`_test_assist_empty_final_nudge_e2e.py`).

## 배운 것

1. **모델이 "없다"고 하면 먼저 도구의 매칭 규칙을 의심하라.** 정확 일치만 받는 인자는 약한 모델에게 "없음"으로 보인다.
   유일할 때만 보정하고, 모호하면 후보를 돌려주는 것이 정답.
2. **팩트에 이름만 주면 모델은 구조를 추측한다.** 시트·열까지 주면 첫 호출이 맞는다. 토큰 몇 백 개 값어치는 충분히 한다.
3. **정렬·순위·집계는 도구가 한다. 모델은 도구 결과를 옮겨 적기만 하게 하라.** 눈으로 고른 순위는 21행에서도 틀린다.
4. **빈 final 은 모델의 흔한 실수다.** 근거가 있으면 버리지 말고 한 번 재촉하라. 재촉은 상한을 둔다.
5. 같은 질문을 **여러 번 반복**해야 보인다 — 3회 중 1회만 정답이던 것이 한 번 돌려선 '정상'으로 보였을 것이다.

`61_popup_reopen_lost_ask_and_dead_endpoint_hang.md`(같은 계열 — 도구 0회 날조), 실기 스크립트 `scratchpad/e2e/run_assist_margin_vague.py`.
