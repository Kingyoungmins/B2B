# 55. 한 세션의 연쇄 실패는 한 뿌리를 찾아라 — SBAGENT-293~297 (2026-08-25)

## 사건
한전 인천본부 사용자 세션 하나(14:03~14:21)에서 제보 4건(294·295·296·297)이 나왔다.
따로 보면 "시트 복사 위치 안 됨", "시트 이동 안 됨", "필터 안 걸림·전단계 OFF",
"수식이 값으로 복사됨" — 전부 다른 증상. 첨부 로그를 겹쳐 보니 **한 작업 흐름의 연쇄**였다:

1. copy_sheet 의 before/after 가 프롬프트 문서에 없어 모델이 add_sheet+copy 합성으로 우회
2. "옮겨줘" 재요청 — move_sheet 헬퍼가 아예 없어 모델이 ① ctx.Sheets 원시 COM(AttributeError
   원문 노출) ② import datetime(정적검사 전체 실패) ③ 임시시트 복사→삭제→rename 교체(금지
   패턴)를 차례로 지어냄
3. 수정 실패가 수정 모델(뒤 스텝 OFF)과 겹쳐 전 단계 OFF → "계속 요청해도 진행 안 됨"
4. 그 위에 AI 도움까지 YAML 액션 미파싱(293)으로 먹통 — 사용자는 완전히 고립

## 교훈
1. **엔진 무죄, 생성 계층 유죄가 반복된다.** copy_sheet(before/after)·ctx.copy(수식 보존)·
   Worksheet.Move 전부 실기 COM 검증으로 정상이었다. 실패는 전부 ① 프롬프트 문서에 없는
   파라미터 ② 없는 헬퍼(모델이 지어냄) ③ 게이트의 과잉 차단에서 났다. 제보가 "기능이 안
   된다"여도 엔진부터 의심하지 말고 **모델이 실제로 생성한 코드**(step.code.full)를 먼저 봐라.
2. **헬퍼가 없으면 모델은 지어낸다 — 공백이 곧 크래시다.** ctx 에 move_sheet 가 없다고 모델이
   포기하지 않는다. 원시 COM·금지 패턴으로 흉내내다 더 나쁘게 죽는다. 작업 계열(시트 배치)을
   지원하려면 CRUD 대칭(add/copy/move/rename/delete)을 채워라.
3. **게이트는 '해로움'만 막아야 한다.** import datetime 은 무해한데(모듈이 이미 주어짐) 일률
   차단이 95초 리셋 사이클을 통째로 실패시키고 전단계 OFF 연쇄까지 갔다. 차단 규칙엔 반드시
   "이게 실제로 해로운가"를 물어라. 허용으로 바꿀 땐 **정적 게이트·클라 정규식·런타임 샌드박스
   세 층을 같은 정책으로** — 한 층만 열면 정적 실패가 런타임 실패로 바뀌어 더 나빠진다
   (__import__ 부재 함정).
4. **오류 원문은 사용자용 문장이 아니다.** 'object has no attribute Sheets' 원문 노출이
   "ctx에서 시트를 찾을 수 없다"는 오역된 제보를 만들었다. __getattr__ 에서 "무엇을 쓰라"로
   바꿔주면 재생성 프롬프트의 방향도 잡힌다(hasattr 의미 보존 위해 AttributeError 유지).
5. **라이브(채팅) 런도 코드 전문을 남겨라.** codeHash 만으로는 "수식이 값이 됐다" 제보를 영영
   확정할 수 없었다(297). step.code.full 은 파이프라인 전용이었다 — 진단 로깅은 실행 경로
   전부에 대칭으로.
6. **모델의 리터럴 복사는 믿지 마라.** 사용자가 쓴 '전산화번호'를 '전자화번호'로 옮기는 한 글자
   오타가 반복 실측됐다. 한글 한 글자 차이 리터럴 게이트로 잡되, 숫자 차이(연도·월)는 정상
   변형이라 오탐 가드가 본체다.
