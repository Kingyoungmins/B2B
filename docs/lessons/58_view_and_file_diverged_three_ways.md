# 58. 화면과 파일이 갈라진 세 가지 — 조용히 틀린 결과를 내주던 경로들

날짜: 2026-09-08 ~ 09-09 / 버전: 0.8.4

셋 다 증상이 같다. **화면에는 제대로 보이는데 실제 파일은 다르다.** 오류도 안 나고
"적용됨"으로 끝나서, 사용자가 받아 간 뒤에야 알게 된다. 자동화 도구에서 가장 나쁜 부류다.

---

## ① 결과편집 뒤 다운로드하면 '옛 결과'가 받아졌다 (크리티컬)

### 증상
사용자 재현 순서:
1. 원본에 19단계 스킬 전체실행 → 결과 파일 받기(정상)
2. **결과편집** → 결과를 라이브 화면으로 불러오기
3. 스킬 하나 더 추가 → 라이브에 적용됨(화면에 보임)
4. 생성기 파일 칩의 [다운로드] → **3번 스킬이 빠진 파일**이 받아짐

로그가 그대로 말해준다(세션 `20260903-145026`):

```
14:52:03  http.run_full_pipeline.response  applied=19      ← 전체실행 결과 저장
14:52:11  excel.replace.opened                              ← 결과편집(라이브 교체)
14:52:34  python_com.run.ok  structural=['insert_cols:VIEW:C+1']  ← 새 스킬 라이브 적용
14:52:39  (다운로드)  → 받은 파일 = 14:52:03 결과              ← 새 스킬 없음
```

### 원인
`downloadCurrentWorkbookFile` 은 **직전 전체실행 결과(`window.lastRunnerOutputs`)를 라이브 저장보다 우선**한다.
이 우선순위 자체는 예전 버그(전체실행 후 다운로드하면 원본이 받아지던 문제)를 막으려고 넣은 것이다.
그런데 **결과편집이 그 결과를 라이브로 흡수한 뒤에도 항목이 그대로 남아** 낡은 결과가 계속 이겼다.

라이브로만 스킬을 만들면 이 항목이 아예 없어서 정상이었다 — 사용자가 짚은 재현 조건과 정확히 일치한다.

### 수정
- 결과편집이 라이브로 불러온 항목에 `liveAbsorbed` 표시(불러온 `excelId` 만).
- 다운로드는 흡수된 항목을 건너뛰고 `/api/excel/save`(라이브 현재 상태)로 간다.
- 부수 구멍도 함께: **결과편집을 두 번 누르면** 옛 결과가 라이브를 다시 덮어 추가 스킬이 화면에서도
  사라졌다 → 재클릭 목록에서도 흡수분 제외(전부 흡수면 재적용 폴백).
- 결과를 라이브에 **안** 불러온 파일의 '결과 우선' 분기는 그대로 뒀다(원본 오다운로드 방지).

회귀: `test_runs/_test_result_edit_download.js` — 필터 로직을 실제로 실행해 흡수 전/후/타 파일을
행동으로 확인하고, `lastRunnerOutputs` 를 새로 쓰는 지점이 실행기 완료 **한 곳뿐**임을 가드로 잠갔다
(다른 경로가 새 항목을 만들면 흡수 표시가 우회된다).

## ② match_fill 이 다른 달 블록까지 전부 채웠다

### 증상
"이름 맞춰 채우기"를 했더니 의도한 표(7행)뿐 아니라 아래에 반복된 다른 달 표의 같은 상품명까지
전부 덮였다. 로그: `match_fill:MVNO상품명별집계->Sheet1:58 matched` — **58행**이 채워졌다.

실제 파일을 열어보니 답이 나왔다. 대상 시트에 `구분` 헤더로 시작하는 **같은 표가 8번 반복**
(행 4, 28, 44, 59, 75, 82, 98, 114, 139)돼 있고 상품명이 블록마다 똑같이 등장한다.

### 원인
`match_fill` 은 대상 키열을 헤더 아래부터 **시트 끝까지** 스캔해 이름이 맞는 행을 전부 채운다.
월별 요약처럼 같은 표가 아래로 반복되는 시트에서는 과거 블록이 전부 덮인다.

사용자가 시도한 `rows=7` 도 소용없었다 — "7행만"이 아니라 **"행 7부터 끝까지"** 로 해석된다(이중 함정).

### 수정
기본 `scope="block"`: 대상 키열에 헤더 라벨(예 `구분`)이 **다시 나오면 다음 블록**이므로 그 앞에서 멈춘다.
헤더가 반복되지 않는 일반 시트는 동작이 완전히 같다. `scope="all"` 로 예전 동작, 끝을 명시한
`rows=(시작,끝)` 은 그대로 존중.

회귀: `test_runs/_test_match_fill_block_scope.py` — 진짜 Excel 로 다중 블록 시트를 만들어
"이번 달만 채우고 지난달 블록 보존", `scope="all"`, 명시 rows 를 되읽어 확인.

## ③ "합계 행은 제외합니다" 라던 코드가 그 행의 수식을 지웠다

### 증상
원가 열 채우기 단계가 *"합계/평균 요약 행(24행)은 제외합니다"* 라고 설명해 놓고,
**C24 의 기존 수식이 사라졌다.** 매출 열은 멀쩡했다.

### 원인
생성된 코드가 제외를 이렇게 구현했다:

```python
for r in names:
    if nm is None or "합계" in str(nm):
        out.append([None])          # ← '제외' 의도
    else:
        out.append([cost.get(...)])
ctx.write(sheet, f"C{hdr+1}", out, overwrite_formulas=True)   # ← 통짜 기록
```

엔진에서 `None` 은 **셀 비우기**다. 말은 "제외"인데 실제로는 "빈값으로 덮어쓰기"였다.
매출 열이 무사했던 건 `ctx.match_fill` 을 썼기 때문이다 — 매칭된 행만 연속 구간으로 쓰고
요약 행은 아예 안 건드린다.

### 수정
`ctx.write` 에서 **행 전체가 None 이면 그 행은 건드리지 않는다**(연속 구간별 기록).
판정은 `_as_2d` 가 `None` → `""` 로 바꾸기 **전** 원본으로 한다(변환 후엔 구분이 안 된다 — 처음에
변환본으로 판정해 테스트가 잡아냈다).

의미가 바뀌면 안 되는 내부 호출자는 `skip_none_rows=False` 로 예전 동작 고정:
`write_cell`(단일 셀 명시 None = 비움), `match_fill`, 조회 채우기 헬퍼(빈 값 = 비움).

회귀: `test_runs/_test_write_skip_none_rows.py` — 진짜 Excel 로 수식 보존·구간 분할·전부 None 무반응·
내부 헬퍼 예전 의미를 되읽어 확인.

## 배운 것

1. **"제외"와 "빈값 기록"은 다른 일이다.** 헬퍼 API 에서 `None` 의 의미를 정하지 않으면 생성 코드가
   둘을 섞는다. 지금 규약: 행 전체 None = 손대지 않음, 셀을 비우려면 `ctx.clear`.
2. **범위 기본값은 '지금 보이는 표'여야 한다.** 시트 끝까지가 기본이면 반복 블록 시트에서 조용히
   과거 데이터를 파괴한다. 넓히는 건 옵션(`scope="all"`)으로.
3. **우선순위 규칙에는 만료 조건이 필요하다.** "실행 결과가 라이브보다 우선"은 결과가 라이브로
   흡수되는 순간 무효가 돼야 하는데, 그 전이(轉移)를 아무도 안 적어 뒀다.
4. **진단은 로그 → 실물 파일 순서로.** 세 건 다 트레이스에서 시각·수치를 먼저 확정하고
   (58 matched / applied=19 / structural), 실제 xlsx 를 열어 구조를 확인한 뒤에 코드를 고쳤다.
   추측으로 시작했으면 셋 다 엉뚱한 곳을 고쳤을 것이다.
5. **회귀는 실물 Excel 로.** 이 셋은 전부 COM 동작(Value2=None, 연속 구간 쓰기, 블록 경계)이라
   목(mock)으로는 증명이 안 된다.
