# 59. 싱글 exe 가 "액세스할 수 없습니다" — EDR 이 자동압축해제 방식을 막는다

날짜: 2026-09-09 / 버전: 0.8.4

## 증상

빌드는 정상 완료(`[OK] single build complete.`, 신선도 검사 통과)했는데, `dist\AX-Cell.exe` 를
더블클릭하면 Windows 오류창이 뜬다:

> 지정한 장치, 경로 또는 파일에 액세스할 수 없습니다. 이 항목에 액세스할 수 있는 권한이 없는 것 같습니다.

파일은 멀쩡하다 — `Get-FileHash` 로 **읽기는 된다**. 실행만 막힌다.
`Start-Process` 로 띄우면 `Access is denied` 예외가 **동기적으로** 난다(= 프로세스 생성 단계 차단).

## 원인을 어떻게 좁혔나 — 변수 하나만 바꾸는 대조 실험

증상만 보면 "새로 빌드한 exe 가 오탐당했다" 인데, 그러면 **무엇이** 오탐 대상인지 모른다.
런처인지, 서버인지, 새 코드인지. 그래서 같은 런처로 **페이로드만 바꿔** 4개를 컴파일해 실행해 봤다.

| 실험 | 런처 | 페이로드 안 `B2B_Server.exe` | 결과 |
|---|---|---|---|
| P82 | 동일 | 0.8.2 | **허용** |
| P84 | 동일 | 0.8.4 | **차단** |
| P84_s82 | 동일 | 0.8.4 패키지인데 서버만 0.8.2 | **허용** |
| P82_s84 | 동일 | 0.8.2 패키지인데 서버만 0.8.4 | **차단** |

여기에 방식별 실행도 대조했다:

| 실행 방식 | 결과 | 차이점 |
|---|---|---|
| 싱글 exe (0.8.4) | 차단 | %TEMP% 에 풀어서 실행 |
| 포터블 폴더의 `B2B_ver0.8.4.exe` | 허용 | 자기 폴더에서 바로 실행 |
| `B2B_Server.exe` 직접 실행 | 허용 | 추출 없음 |

**차단 조건은 두 가지가 동시에 성립할 때다: ① %TEMP% 로 실행파일을 풀어서 실행(드로퍼 동작)
② 평판 없는 새 바이너리.** 둘 중 하나만이면 통과한다.

## 범인 확정

Windows 이벤트 로그에서 실행 시각과 정확히 일치하는 기록을 찾았다:

```
로그: CrowdStrike-Falcon Sensor-CSFalconService/Operational
13:10:46  Id=3  A process was blocked because malicious behavior was detected.
```

AhnLab V3 도 깔려 있지만 V3/Defender 쪽에는 탐지 기록이 없었다. **CrowdStrike Falcon 의 행위 기반
차단**이고, 서명 탐지가 아니다. 즉 파일에 악성코드가 있어서가 아니라 **"작은 exe 가 임시폴더에
실행파일을 떨구고 실행"** 이라는 패턴이 드로퍼와 같아서 막힌 것이다 — 전형적인 오탐.

0.8.2 는 통과하는데 0.8.3·0.8.4 는 막힌다. 0.8.2 해시가 이미 평판/허용을 얻었기 때문으로 보인다
(0.8.3 은 일주일 전 빌드인데도 막힌다 = "오늘 새로 만들어서" 가 아니다).

## 대응

1. **당장 쓰려면 포터블 패키지로 배포한다.** `dist\B2B_ver0.8.4\` 폴더(또는 함께 만들어지는
   `B2B_ver0.8.4_portable.zip`)는 추출 동작이 없어 차단되지 않는다 — 실측으로 실행 확인했다.
2. **싱글 exe 를 계속 쓰려면** 보안 담당에게 CrowdStrike 테넌트에 해시 허용(allowlist)을 요청한다.
   근거로 위 이벤트 로그(시각 + Id 3)와 대조 실험 표를 그대로 첨부하면 된다.
3. 근본 해결은 **코드 서명 인증서**다. 서명하면 평판이 붙어 드로퍼 패턴 점수를 낮춘다.

## 배운 것

- **"권한이 없습니다" 는 파일 권한 문제가 아닐 수 있다.** ACL·읽기가 멀쩡한데 `Start-Process` 가
  즉시 Access denied 면 EDR 의 프로세스 생성 차단을 먼저 의심하라. 확인처는
  `Microsoft-Windows-Windows Defender/Operational` 이 아니라 **설치된 EDR 자신의 이벤트 로그**다
  (`Get-WinEvent -ListLog * | ? LogName -match 'CrowdStrike|Falcon|AhnLab'`).
- **오탐 조사도 대조 실험으로.** "새 빌드라서" 같은 서사는 검증이 안 된다. 페이로드 하나만 바꿔
  4번 컴파일하니 원인이 30분 만에 확정됐다.
- **배포 방식은 보안 정책의 영향을 받는 설계 변수다.** 단일 exe 편의성이 사내 EDR 에서는
  배포 불가로 이어질 수 있다 — 포터블 zip 을 항상 같이 만들어 두는 이유.

관련: `BUILD.md`, `OFFLINE_PORTABLE_BUILD.md`, `single_exe/B2BSingleExeLauncher.cs`(%TEMP% 추출 로직).
