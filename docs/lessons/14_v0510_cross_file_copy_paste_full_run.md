# 0.5.9~0.5.10 교훈: 복붙 캡처와 교차파일 전체실행

이 문서는 0.5.9의 복붙/셀삭제 캡처 기능과, 0.5.10 시점에 잡은 **교차파일 복붙 전체실행 버그**의 구현·함정·근본원인을 정리합니다.
`09_v059_copy_paste_capture_scenarios.md`는 수동 테스트 시나리오이고, 이 문서는 "왜 그렇게 만들었는지"와 재발 방지 기록입니다.

정리 기준일: 2026-06-18

## 복붙/셀삭제 캡처가 하는 일

- 📋 복붙 캡처 / 🗑 셀 삭제 캡처: 우측 라이브 Excel에서 사용자가 한 Ctrl+C/Ctrl+V(또는 Delete)를 역추적해 `ctx.paste_copied(...)` / `ctx.clear(...)` 스킬 스텝으로 저장하고, 전체실행 때 **좌표 그대로 재현**합니다. LLM이 "값이냐 수식이냐"를 추측하지 않으므로 복붙 버그가 사라집니다.
- 소스 = 클립보드 'Link' 포맷, 대상 = 붙여넣은 위치.

### 클립보드 'Link'는 항상 R1C1 — 전체열/행/다중영역 변환 함정

실측으로 확인한 형태입니다.

- 일반 `R1C1:R6C5` → `A1:E6`, 단일 셀 `R2C2` → `B2`.
- **전체 열** A:E → `C1:C5`(행 표기 없음) → `A:E`. **전체 행** 1:6 → `R1:R6`(열 표기 없음) → `1:6`.
- **비연속 다중영역**(Ctrl-클릭) → 콤마 `C1:C3,C5:C5`.

유지 기준:

- R1C1→A1 변환기는 콤마로 영역을 먼저 나눈 뒤 각 영역을 변환해야 합니다. 첫 `:`만 split 하면 전체열/행·다중영역이 깨집니다(예전 버그).
- 비연속 다중영역(`Areas.Count > 1`) 캡처는 재생이 모호하므로 거부합니다. 단일 셀은 붙여넣기 앵커로 정상(소스 크기만큼 자동 확장).

### 클립보드 Link는 붙여넣기/탭전환 후 사라진다 (교차파일 핵심)

- 복사(A) → 탭 전환 → 붙여넣기(B) 과정에서 `CutCopyMode`가 풀려 캡처 시점엔 Link가 없어집니다(`no-clipboard-source`). 같은 파일은 복사→붙여넣기→버튼이 빨라 클립보드가 살아 있어 우연히 됐던 것입니다.
- 유지 기준: 라이브 폴이 `CutCopyMode`가 켜져 있는 동안 클립보드 소스를 전역 스냅샷에 저장하고, 캡처는 라이브 클립보드를 먼저 읽되 없으면 스냅샷(TTL)으로 폴백합니다.

### 대상은 전역 Selection이 아니라 세션 창에서 읽는다

- `app.Selection`은 교차파일/오버레이 상황에서 **소스 워크북**을 가리킬 수 있습니다(붙여넣은 B가 아니라 복사한 A의 선택이 잡힘). `apply-focus-selection` 류 함정과 같은 부류입니다.
- 유지 기준: 대상은 그 세션(excelId=붙여넣은 파일) 워크북의 `Windows(1).RangeSelection`으로 읽습니다.

## 교차파일 복붙 전체실행 버그 (확정 조사)

증상: 교차파일 복붙(예: `청구내역!A1:H13 → 정산!A1`) 캡처도 성공, 단일 적용도 성공인데 **전체실행만** `변경하려는 셀 또는 차트가 보호된 시트에 있습니다`로 실패. 그 뒤 복사했던 **소스(청구내역) 창의 미러 숨김 뷰가 풀려 리본이 보이고**, 그 파일을 제거 후 재업로드하면 "불러올 수 없음"으로 실패.

확정 원인:

- 전체실행 Python 경로(`runVbaPipelinePreferLive`의 python 분기)가 스텝을 **"지금 보고 있는 탭" 세션**에서 실행했습니다. 교차파일 스텝의 대상(정산서)이 현재 탭이 아니면 엉뚱한 세션(소스)에서 돌아갑니다.
- 백엔드(`_run_python_on_session_impl`)는 **그 세션 워크북만 보호 해제**합니다. 그래서 붙여넣을 대상(정산서)은 보호된 동반 워크북으로 남아 쓰기가 막힙니다.
- 게다가 라이브 경로는 붙여넣기 소스로 **살아있는 소스 워크북을 직접 읽어** 그 창을 활성화/교란합니다 → 미러 숨김 뷰가 풀리고 파일이 잠깁니다.

처방(확정):

- **교차파일 복붙(`src_book ≠ dst_book`) 스텝이 하나라도 있으면 전체실행을 격리 파이프라인**(VBA가 쓰는 `runIsolatedLivePipelineSteps` → `/api/excel/run-vba-pipeline`)으로 보냅니다. 격리 인스턴스는 소스를 **throwaway `SaveCopyAs` 복사본**으로만 읽어 라이브 소스를 전혀 건드리지 않고, 대상(ftarget)만 보호 해제·실행·반영합니다. (백엔드는 무수정 — 기존 격리 경로 재사용.)
- 캡처 스텝에 `targetFileId = 붙여넣은(대상) 파일`을 박습니다. 대상 추론기는 `src_book`(교차파일일 때)을 읽기 소스로 인식해 대상을 `dst_book`으로 잡게 합니다.
- 캡처 복붙/셀삭제는 **LLM 자동복구에서 제외**합니다(코드의 `[복붙 캡처]`/`[셀 삭제 캡처]` 마커로 판별). 재생성하면 동작이 바뀌고 같은 실패를 반복("박힘")합니다.
- **단일 파일 Python 전체실행은 기존 라이브 경로 그대로 둡니다.** 건드리면 창 깜빡임/매크로 막힘이 재발합니다(VBA 격리 경로는 어제 합의대로 손대지 않음).

유지 기준:

- 교차파일은 소스 워크북을 **읽기만 하더라도** 라이브에서 직접 열지 않습니다(뷰/잠금 부작용). 격리 복사본으로 읽습니다.
- 전체실행은 reset 후 재현이라 결과는 **대상 파일에만** 반영되고 소스는 변하지 않습니다.

## 진단 (`vba_pipeline_trace.jsonl`)

- `capture.copypaste.start/dest/source/result`: `openBooks`(두 파일이 같은 인스턴스인지), `clipboardSource`(+`snapUsed`), `via`(session-window/global), `globalSelectionBook`(대상과 다르면 오버레이 포커스 단서), `crossFile`.
- `paste_copied.src`: `in-instance` / `auto-opened-readonly` / `not-open-no-path`.
- **핵심 신호**: `paste_copied.src`만 있고 `pipeline.impl.start` / `pipeline.isolated.*`가 없으면 = 격리가 아니라 **라이브 경로로 실행된 것**. 교차파일인데 이러면 잘못된 경로입니다.

## 체크리스트

1. 교차파일 복붙은 전체실행에서 반드시 격리 경로로(소스는 복사본으로 읽음). 라이브 경로 금지.
2. 캡처 스텝은 `targetFileId = 붙여넣은(대상) 파일`로 고정. 대상 추론은 `dst_book` 기준.
3. 캡처 복붙/셀삭제는 자동복구(LLM 재생성)에서 제외 — 정확 좌표 재생이 목적.
4. 클립보드 Link는 R1C1. 전체열 `Cx:Cy`/전체행 `Rx:Ry`/다중영역 콤마를 변환기가 처리. 다중영역 캡처는 거부.
5. 클립보드는 붙여넣기/탭전환 후 사라질 수 있음 → 복사 중 폴 스냅샷으로 폴백.
6. 대상 선택은 전역 `Selection`이 아니라 세션 창 `Windows(1).RangeSelection`.
7. 단일 파일 Python 전체실행 경로는 건드리지 않는다(회귀 위험).
