# 41. result-edit 라이브 워크북 정체성 보존 — @멘션/이어작업 '파일 못 찾음' (v0.5.17, SBAGENT-171 파생)

## 증상
- 실행기에서 전체실행 → "결과 편집하기"로 결과를 불러와 **이어서 단계를 만들 때**, 생성기 채팅에서
  `@파일/@시트` 로 지정해도 백엔드가 그 파일/시트를 **못 찾는다**.
- 파일 이름 뒤에 `_난수`(실은 `결과_<원본stem>_<타임스탬프>[_<6hex>]`)가 붙어 보임.
- **사용자가 그 접미사를 강제로 맞춰줘도 못 찾음.**
- 시나리오: 30단계 스킬을 전날 15단계까지 + 전체실행, 다음 날 결과 불러와 16단계부터 이어 만들기가 막힘.

## 근본 원인 (코드 확정)
- 실행기 파일출력 전체실행은 결과를 **다운로드용 이름** `결과_<원본stem>_<ts>[_<6hex>].xlsx` 로 저장하고
  RESULTS 에 그 이름으로 등록한다 (`serve_b2b.py` 7977 부근).
- "결과 편집하기"는 그 결과를 `/api/excel/replace` 로 **같은 라이브 세션에 되불러온다**. 이때 라이브 워크북을
  결과 파일명으로 다시 열면 **wb.Name 이 `결과_..._난수` 데코명**이 된다.
- 앱은 파일을 **이름 문자열**로 식별한다: @멘션은 `state.inputs[].name`(원본명)을 LLM 에 *정확 파일명*으로
  주입하고(`mentions.js` 75/182), 백엔드는 그 문자열을 라이브 wb.Name 과 비교/조회한다(VBA `Workbooks("원본")`,
  `If wb.Name="원본"`, Python `ctx.book("원본")`). 라이브가 데코명이면 **원본명과 영영 불일치**.
- `_clean_session_workbook_name` 은 **우리 접두사**(`<32hex>_`, `prestep_<32hex>_`)만 벗긴다. `결과_..._난수`
  데코는 접두사 패턴이 아니라 못 벗긴다 → 데코명이 그대로 wb.Name 으로 새어든다. 타임스탬프까지 박혀
  사용자가 접미사를 추측해 맞출 수도 없다.

## 수정 (백엔드, v0.5.17)
- replace 는 **'같은 세션을 이어서' 콘텐츠만 교체**하는 것이므로 라이브의 정체성은 **'원래 세션 이름'** 이다.
- 새 순수함수 `_resolve_live_identity_name(session_name, incoming, path)`: 세션의 기존 깨끗한 이름을 **최우선
  보존**하고, 없을 때만 들어온 파일명을 접두사 정리한다. 스냅샷 복원(`prestep_<hex>_원본`)도 세션 이름과
  동일 결과라 **회귀 0**.
- `_replace_excel_session_workbook_impl`: `clean_name` 산출을 위 헬퍼로 교체(데코명이 wb.Name 으로 안 샘).
- replace **응답**도 데코명(`name or path.name`) 대신 `clean_name` 반환 → 파일탭/표시명까지 원본명 유지.

## 왜 이 한 수정으로 충분한가 (다른 층은 이미 견고)
- **VBA**: `_normalize_vba_workbook_literals` 가 모든 `"*.xlsx"` 리터럴(=`Workbooks("..")` 뿐 아니라
  `If wb.Name="..")` 비교 포함)을 실제 열린 wb.Name 으로 치환한다 → 정체성만 보존되면 `%20`↔공백 변형도 매칭.
- **Python**: `ctx.book` 은 `_workbook_name_lookup_keys`(unquote + `<12+hex>_` 접두사 제거)로 해석 → `%20`/접두사 OK.
- **전체실행(Q2)**: 명시 전체실행은 항상 **원본부터 pristine 재생**(`_test_fullrun_forces_pristine`)이라 '이어지는
  파일'을 런타임에 따로 쓰지 않는다. 빌드 중 정체성이 원본명으로 보존되면 저장 스킬에 박히는 이름도 원본명 →
  30단계도 끝까지 일관 실행. (정체성 churn 이 빌드 시점에 이름을 오염시키면 저장 스킬까지 오염되므로 이 수정이 전제.)
- **클라 무수정**: @멘션은 `state.inputs`(원본명) 사용, result-edit 핸들러는 응답 `name` 미사용(스냅샷 토글 경로는
  `liveSchema` 만 사용). 데코명은 다운로드 파일명으로만 쓰여 그대로 둔다.
