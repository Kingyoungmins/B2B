# 0.5.6~0.5.9 핵심 교훈 정리

이 문서는 `B2B_ver0.5.6`, `B2B_ver0.5.7`, `B2B_ver0.5.8`, `B2B_ver0.5.9`의 MD 문서를 훑고, 0.5.10 이후에도 반드시 기억해야 할 내용을 모은 요약입니다.

원본 문서는 `docs/lessons/by_version/` 아래에 버전별로 복사해 두었습니다.

## 0.5.6에서 가져갈 교훈

### Python COM은 빠를 수 있지만, 셀 단위 COM 루프는 금지

0.5.6은 라이브 Python COM을 본격 기준으로 둔 시점입니다. 구조적으로 이미 떠 있는 Excel을 직접 제어하므로 openpyxl보다 UX에 맞지만, `for row -> for cell -> COM 호출` 패턴은 앱을 오래 붙잡습니다.

유지 기준:

- Python COM 코드는 가능한 한 범위 단위로 읽고, 메모리에서 계산하고, 범위 단위로 씁니다.
- 셀 단위 루프가 필요해 보이는 작업은 VBA 또는 전용 bulk ctx API를 우선 고려합니다.
- COM 호출 예산, deadline, 쓰기 저널, 실패 시 롤백은 선택 기능이 아니라 기본 안전장치입니다.

### 값/수식 의도는 생성 단계에서 강하게 분리해야 함

0.5.6 문서부터 `값만`, `수식`, `그냥 복사`의 의미가 계속 문제로 등장합니다.

유지 기준:

- "값만", "계산값만"은 수식 문자열이 아니라 현재 계산 결과 값입니다.
- "복사", "복붙"만 있으면 값+수식+서식 보존입니다.
- 수식 셀을 덮어쓰는 것은 사용자가 대상 범위를 지정했으면 허용할 수 있습니다. 단, 합계행/요약행은 수식이라서가 아니라 데이터 행이 아니기 때문에 제외합니다.

### 사후 검증은 실패 판정이 아니라 보조 신호

0.5.6의 `changedCells == 0` 교훈은 중요합니다. 변경 없음은 실제 오류일 수도 있지만, 데이터가 이미 같은 값이거나 조건에 맞는 행이 없을 수도 있습니다.

유지 기준:

- change probe 실패나 변경 0건을 무조건 오류로 강등하지 않습니다.
- "적용됨" 대신 "변경 없음 · 확인 필요" 같은 비파괴 상태로 보여주는 것이 안전합니다.
- 의미적 오류, 예를 들어 회사명 배열이 금액 칸에 들어간 문제는 사후 변경 감지만으로 못 잡습니다. 프롬프트/정적 검사에서 예방해야 합니다.

### VBA 정적 검사는 오탐을 경계해야 함

0.5.6에서 `Exit For`, `color`, `vendor` 같은 정상 코드가 `or`로 끝난다고 오탐된 이력이 있습니다.

유지 기준:

- 정규식 기반 VBA 검사는 단어 경계와 문맥을 반드시 봅니다.
- 차단 규칙을 추가하면 정상 샘플도 같이 돌립니다.
- "안전"이라는 이름으로 정상 코드를 막으면 사용자는 같은 작업을 반복 요청하게 되고, 결국 신뢰가 떨어집니다.

### 취소는 실제 COM 중단이 아니라 결과 무시 + 원상 복구

VBA `Application.Run`과 Excel COM 호출은 동기 실행이라 fetch abort만으로 즉시 중단되지 않습니다.

유지 기준:

- 작업 중단은 "실행 중인 Excel 내부 작업을 즉시 죽임"으로 설계하지 않습니다.
- 취소 토큰으로 늦게 도착한 성공/오류를 무시하고, 원본 스냅샷에서 남은 enabled 스텝만 재적용합니다.
- 사용자에게는 멈춘 것처럼 보이지 않게 UI 상태와 복구 경로를 먼저 안정화합니다.

## 0.5.7에서 가져갈 교훈

0.5.7의 핵심 MD 해시는 0.5.6과 거의 동일했습니다. 즉, 코드나 UI에서 변화가 있었더라도 문서화된 교훈은 새로 남지 않았습니다.

유지 기준:

- 버전이 바뀌었는데 README/조사 리포트에 교훈이 없으면, 다음 사람이 같은 문제를 다시 추적해야 합니다.
- 기능 변경이 작아 보여도 "왜 바꿨는지", "어떤 실패를 막는지", "회귀 테스트는 무엇인지"를 최소 3줄이라도 남깁니다.
- `start_b2b.bat`, `start_b2b_native.bat`, single exe처럼 실행 경로가 여러 개인 경우 UI/동작 차이를 문서로 남겨야 합니다.

## 0.5.8에서 가져갈 교훈

### 전체실행 실패는 Excel 보안보다 payload/실행 경로를 먼저 본다

0.5.8의 가장 큰 삽질은 VBA 단일 적용은 되는데 전체실행만 `B2B_RunSkill 매크로를 실행할 수 없습니다`로 실패한 문제였습니다.

확정 교훈:

- Excel 보안 설정이 아니라 저장된 스킬 payload 앞뒤 설명 텍스트와 전체실행의 다른 runner 경로가 핵심 원인이었습니다.
- 서버 주입 직전에는 반드시 실제 `Sub ... End Sub`만 추출해야 합니다.
- VBA 포함 파이프라인은 생성기 전체실행, 스킬 실행기 전체실행, on/off, 삭제, undo/redo 모두 같은 `/api/excel/run-vba-pipeline` 흐름을 써야 합니다.
- Python COM + VBA 혼합 파이프라인도 언어별로 따로 리셋하지 말고 한 파이프라인에서 순서대로 실행합니다.

### 안전 재생성은 반복 루프가 되면 안 됨

0.5.8에서 값만 복사, 수식 셀 값 덮어쓰기, 서식 있는 셀 대상 붙여넣기가 안전 가드에 과도하게 막혔습니다.

유지 기준:

- 복붙 관련 안전 재생성은 사용자의 명시적 의도를 막으면 안 됩니다.
- 안전 가드 실패 후 같은 엔진으로 무한 재생성하지 않습니다.
- 1회 재생성 후 같은 위험이 남으면 VBA 우회 또는 명확한 차단으로 끝냅니다.

### 유사 피벗/복합 조건은 PivotTable보다 딕셔너리/배열 집계를 우선

VBA에서 실제 PivotTable을 만들면 캐시, 필드명, 범위 지정 실패 확률이 큽니다.

유지 기준:

- "피벗"이라는 단어가 없어도 행 기준, 열 기준, 값 합계가 있으면 유사 피벗으로 봅니다.
- 안정성은 `Dictionary` + 배열 집계 + 결과 시트 쓰기가 더 낫습니다.
- 전화번호/가입번호/발신번호 같은 식별자는 `.Text`로 읽고 텍스트 서식으로 써서 선행 0을 보존합니다.

### Sonnet/정적 리포트에서 반복 위험 패턴을 코드 규칙으로 승격

0.5.8 VBA 회귀 리포트는 반복 위험을 잘 정리했습니다.

반드시 기억할 패턴:

- 미매칭 행에 `0` 덮어쓰기 금지. 매칭 없는 행은 유지합니다.
- 합계행/소계행/부가세포함 행을 데이터 범위에 포함하지 않습니다.
- manual calculation 상태에서 값 복사 전 재계산을 고려합니다.
- 날짜/시간은 무작정 `Value2` 일괄쓰기하면 서식이 깨질 수 있습니다.
- `ActiveWorkbook` 무검증 참조는 위험합니다. 파일명/시트명으로 찾아야 합니다.
- workbook 탐색 후 `Nothing` 판별이 잘못되면 미발견을 묵살합니다.

## 0.5.9에서 가져갈 교훈

### 앱 멈춤은 LLM 품질 문제가 아니라 실행 구조 문제일 수 있음

0.5.9에서 HCN류 다중 가입번호 매칭 합산, 조건+for문 시간 환산 같은 요청이 Python COM으로 생성되면 WebView가 멈추는 사례가 있었습니다.

유지 기준:

- Python COM 코드가 생성되더라도 멈춤 위험 패턴이면 적용 전 막아야 합니다.
- 다중 토큰 분리, 다른 파일 열 매칭, 합산, 대상 열 쓰기 작업은 VBA 우선 라우팅합니다.
- WebView만 멈추고 Excel은 움직이면 Python COM/Excel COM 큐 고착 가능성을 먼저 봅니다.
- 장시간 실행 후 버벅임은 좀비 Excel PID, 미러 폴링, 세션 정리 누락을 함께 봅니다.

### "수식이 있으니 보존"이 아니라 "데이터 행인지"를 판단해야 함

0.5.9에서 H141 같은 합계 수식이 없어지는 문제가 있었습니다. 반대로 수식 셀이라도 사용자가 명시적으로 채워 넣으려는 데이터 셀일 수 있습니다.

유지 기준:

- 기존 수식 존재 여부만으로 쓰기를 차단하지 않습니다.
- 데이터 행 범위를 먼저 정하고, 합계/소계/부가세포함/총계 행은 데이터가 아니므로 제외합니다.
- 대상 전체 열을 1열 배열로 다시 쓰지 않습니다. 매칭된 데이터 행의 대상 셀만 씁니다.
- `None` 행을 필터링해 위로 당겨 쓰는 패턴은 행 정렬을 망가뜨리므로 차단합니다.

### 복붙 캡처는 LLM 추측보다 안전한 경로

사용자가 실제 Excel에서 Ctrl+C/Ctrl+V로 수행한 작업은 의도를 말로 해석하는 것보다 캡처하는 편이 안전합니다.

유지 기준:

- "그냥 복사"는 수식/서식/병합을 포함한 Excel 네이티브 복사입니다.
- "값만 복사"는 계산 결과 값만 씁니다.
- 복붙 캡처는 붙여넣기 직후 눌러야 합니다. 그 사이 다른 복사/Esc가 있으면 소스 정보가 사라집니다.
- 전체 열/행 복붙은 롤백 한계가 있으나 전체실행 reset은 원본 기준이라 재현에는 문제가 없습니다.
- 교차파일 복붙은 소스 파일이 업로드되어 있으면 전체실행에서 닫혀 있어도 읽어 재현해야 합니다.

### 시트명/파일명은 번역하지 않는다

0.5.9 피드백에서 `통합인터넷(국제)`를 `통합internet(국제)`처럼 이해하는 문제가 있었습니다.

유지 기준:

- `@범위[...]` 안의 파일명/시트명/주소는 원문 문자열로 고정합니다.
- LLM이 자연어로 번역하거나 정규화하지 못하게 프롬프트와 정적 검사를 둡니다.
- 시트명을 못 찾으면 비슷한 이름으로 조용히 대체하지 말고, 원문 후보와 실제 시트 목록을 기준으로 복구합니다.

### 음수 부호는 금액 파싱에서 반드시 보존

셀에 음수가 있을 때 양수로 취급하는 생성물이 반복됐습니다.

유지 기준:

- `Abs`, `Replace("-", "")`, 괄호 음수 제거 같은 패턴은 요청이 명시하지 않으면 위험합니다.
- 금액 문자열 정리 시 `-1,234`, `(1,234)` 같은 음수 표기를 보존합니다.
- 합산/차감 요청은 실제 셀 값의 부호를 유지합니다.

## 앞으로 새 문제를 고칠 때 체크리스트

1. 단일 적용과 전체실행이 다르면 Excel 보안보다 payload 정규화와 실행 경로 차이를 먼저 본다.
2. VBA 포함 파이프라인은 하나의 공통 재적용 함수로만 실행한다.
3. Python COM이 생성되어도 셀 단위 루프, 다중 파일 매칭, 다중 토큰 합산이면 적용 전 차단하거나 VBA로 우회한다.
4. 수식 셀이라는 이유만으로 값 쓰기를 막지 않는다. 데이터 행인지 요약 행인지로 판단한다.
5. 매칭 없는 행은 유지한다. `Else 0`으로 오염시키지 않는다.
6. 전체 열을 다시 쓰지 말고 변경 대상 셀만 쓴다.
7. 파일명/시트명/@범위 원문은 번역하지 않는다.
8. 전화번호/가입번호/발신번호는 텍스트로 읽고 써서 선행 0을 보존한다.
9. 금액 파싱은 음수 부호를 유지한다.
10. 복붙 의도는 가능하면 캡처 기반으로 재현하고, "값만"과 "그냥 복사"를 절대 섞지 않는다.
11. 안전 가드는 사용자의 명시적 의도를 막지 않는 선에서만 작동해야 한다.
12. 큰 삽질을 하면 조사 리포트, 최소 재현 시나리오, 회귀 테스트를 같은 날 문서로 남긴다.
