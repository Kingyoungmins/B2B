# 제미나이(Gemini)에게 물어볼 때 — 권장 프롬프트

## 사용법
- **방법 A(권장)**: 아래 [프롬프트 A]를 붙여넣고, 이어서 `직무발명신고서_초안_v0.6.0.md` 전문을 첨부.
  → 초안의 약점을 공격하게 해서 보강 포인트를 얻는다(교차 검증).
- **방법 B**: 아래 [프롬프트 B]로 백지에서 독립 작성시켜 내 초안과 비교. 두 결과의 교집합이
  진짜 핵심, 차집합이 놓친 소재다.

## [프롬프트 A] 초안 비평·보강 (권장)

```
너는 소프트웨어/AI 분야 특허 명세서 작성 경험이 많은 한국 변리사다.
아래는 사내 직무발명신고서 초안이다. 출원 품질을 높이기 위해 다음을 수행하라.

1) 신규성·진보성 관점에서 가장 약한 주장 3개를 지적하고, 각각에 대해
   (a) 어떤 공지기술 조합으로 거절될 수 있는지, (b) 청구항을 어떻게 좁히거나
   요소를 추가하면 방어되는지 제안하라.
2) [핵심 1]~[핵심 4] 각각에 대해 독립항 1개 + 종속항 3개를 한국 특허 청구항
   문체(구성요소 나열식)로 다시 써라.
3) 침해 입증 용이성 관점에서, 경쟁사가 회피설계하기 쉬운 표현을 찾아
   더 넓게/기능적으로 다시 써라.
4) 발명의 설명에서 실시예가 부족해 뒷받침(제33조) 문제가 생길 수 있는 부분을 지적하라.
5) 유사 선행기술로 조사해볼 만한 검색 키워드(한국어/영어)와 IPC/CPC 분류 후보를
   제시하라.
6) 다음 3개 차별점을 진보성(현저한 효과) 논거로 청구항·효과란에 살리는 방안을 제시하라:
   (i) 교차파일(다중 워크북 횡단) 절차의 저장 및 '파일 세트 교체' 재실행,
   (ii) 저사양 장치(4코어 CPU/12GB RAM/HDD) 완주를 보장하는 격리 인스턴스 1개·단일
        요청 배치 구조, (iii) 자체 파서 없이 기설치 Excel 을 구동해 그 Excel 이 여는
        전 확장자(.xls/.xlsx/.xlsm/.xlsb/.csv 및 위장 확장자)·전 버전을 흡수하는
        위임형 호환 구조.

절대 규칙:
- 실존을 확인하지 못한 특허번호·논문 제목을 만들어내지 마라. 선행기술은
  "이런 종류의 기술이 존재할 가능성" 수준으로만 언급하고, 검색 키워드로 제시하라.
- 초안에 없는 기능을 상상해 추가하지 마라. 근거는 초안 본문으로 한정한다.

[여기에 직무발명신고서_초안_v0.6.0.md 전문 붙여넣기]
```

## [프롬프트 B] 독립 작성 (비교용)

```
너는 소프트웨어/AI 분야 특허 명세서 작성 경험이 많은 한국 변리사다.
아래 시스템 설명을 읽고, 사내 직무발명신고서를 다음 양식으로 작성하라:
1. 발명의 명칭 / 2. 기술분야 및 종래기술(2-1 분야·목적, 2-2 유사 공지기술,
2-3 종래 문제점) / 3. 목적·효과(3-1 극복 방법, 3-2 기타 효과) /
4. 발명의 설명(구성도+구성 설명, 플로우차트+단계 설명) / 5. 보호받고자 하는 사항.

절대 규칙: 실존 확인 안 된 특허번호·논문명 창작 금지(검색 키워드로 대체).
설명에 없는 기능 상상 금지. 도면은 ASCII 로.

[시스템 설명]
로컬 PC 에 설치되는 B2B 정산 자동화 프로그램. 구성: C# 네이티브 셸(WebView2) +
웹 UI(JS) + 로컬 Python 실행 서버(win32com) + 실제 Microsoft Excel.
핵심 동작:
(1) 실제 EXCEL.EXE 창을 자식창화 없이(top-level 유지 + 캡션 제거 + 무활성 배치 +
    화면밖 파킹) 앱 UI 우측에 오버레이 임베딩 — 셀 클릭/선택 등 네이티브 입력 보존.
(2) 사용자의 자연어 지시를 LLM 이 Python/VBA '스킬 코드'로 변환, 적용 직전 정적
    게이트 검사 후 라이브 Excel(원본은 절대 안 열고 세션별 작업사본)에 COM 으로 실행.
    실패 시 원인 분류(환경오류/캡처스텝/기검증 스킬은 재생성 금지) 후 LLM 재생성과
    Python↔VBA 엔진 전환(단방향 사다리, 복구 산출물은 게이트 우회 표지로 무한루프 차단).
(3) 스텝들의 파이프라인을 스킬(zip)로 저장. 전체실행은 별도 숨김 Excel 인스턴스에서
    '업로드 원본(pristine)'부터 다시 계산하고, 각 스텝 직전 상태를 스냅샷으로 영속화.
    실패 시 라이브 무손상 + 실패 스텝 직전 스냅샷으로 복원해 그 지점부터만 이어실행.
(4) 저장 스킬을 다음 달 파일(파일명·시트명 변형)에 재사용: 코드·메타를 정적 분석해
    (파일,시트) 요구를 추출하되, 스킬이 실행 중 스스로 만드는 시트(추가/개명/복사
    산출물 — 변수 인자 역추적 포함, VBA 비교문 오판 배제)는 요구에서 제외. 업로드
    파일과 5단 유사도(정확→정규화→어간→포함→토큰, 유일 일치시만 채택)로 자동 매칭,
    [요구 시트]↔[실제 시트] UI 로 사람이 확정, 실행 직전에만 코드 리터럴을 치환한
    사본을 실행(저장본 불변).
(5) 사용자가 라이브 Excel 에서 직접 한 복사/붙여넣기를 키보드 후킹 없이 캡처:
    클립보드의 Excel 전용 Link 포맷에서 소스(북/시트/범위)를, 세션 창의
    RangeSelection 에서 대상을 역추적해 좌표 기반 결정적 재생 스텝으로 저장.
    재생 시 소스 파일이 안 열려 있으면 이름 정규화 역조회로 자동 오픈.
(6) 부가: 확장자 위장 파일(.xls 인 HTML) 시그니처 판별 후 해시 고정 임시명으로 변환
    오픈(시트명 재현성), 시트명 31자 제한 등 Excel 제약을 7단 이름해석 폴백(유일
    매칭시만 완화)+쓰기측 절단으로 흡수, 원격(VDI) mouseup 유실(~7%)을 눌림-즉시
    합성 클릭+중복 삼킴으로 보상, 진행률은 실행 락 밖 무락 채널로 보고.
(7) 핵심 차별점(공지기술 대비): ① 교차파일 — "A 파일에서 집계해 B 파일에 기입" 같은
    다중 워크북 횡단 절차를 저장했다가 다음 회차에 '파일 세트'를 통째로 바꿔 재실행
    (캡처·매핑·격리실행·되돌리기 전 계층이 (파일,시트) 2원 키로 동작). ② 저사양 —
    4코어 CPU/12GB RAM/HDD 사무용 PC 에서 수십 스텝·수십만 행 완주(격리 인스턴스
    1개·1콜 배치, 무락 진행률, 타임아웃 서열화, LLM 연산 외부 위임). ③ 호환성 —
    자체 파서 없이 설치된 Excel 을 COM 구동하므로 Excel 로 열리는 모든 시트 확장자와
    모든 Excel 버전에 대응, 서식·수식·피벗 무손실.
```

## 주의사항 (제미나이 답변 검수 포인트)

1. **특허번호 검증**: 제미나이가 그럴듯한 특허번호(예: KR10-XXXXXXX)를 제시하면
   반드시 KIPRIS(kipris.or.kr)에서 실존·내용 일치를 확인하라. LLM 은 특허번호를
   자주 지어낸다.
2. **기능 창작 검증**: 답변이 우리 제품에 없는 기능을 전제로 청구항을 쓰지 않았는지
   초안 대조.
3. **청구항 광협**: 너무 넓으면(예: "LLM 으로 엑셀을 조작하는 방법") 공지기술로 거절,
   너무 좁으면(함수명 수준) 회피설계가 쉬움 — 구성요소 3~5개 수준의 중간 폭인지 확인.
4. 결과물은 참고용이고, 최종 청구항은 반드시 변리사와 작성.
```
